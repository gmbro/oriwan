# 로그인 복귀·글꼴 위계·반응형 멤버 캘린더

## 반영

- 일반 카카오 로그인, 기본 OAuth 복귀, 로그인된 사용자의 4기 입구는 `/4th/dashboard`로 연결한다. 이전 로그인 링크/쿠키의 `#my-activity`, `#member-features`도 메인으로 정규화한다. 외부 URL·임의 경로 차단은 유지한다.
- 명시적인 내 정보 바로가기는 한 번만 열고 해당 해시를 history.replaceState로 제거한다. Next의 history state와 쿼리는 보존한다. 이전 해시가 남은 주소를 새로고침한 경우 창을 자동으로 열지 않는다.
- TODAY·9.8(화)·서울 시각은 공통 sans 글꼴, 동일한 크기·굵기·색상·줄높이를 상속한다. 항상 한 줄이며 서울 시각은 기존처럼 분 단위 갱신한다.
- 섹션 제목 22~28px, 본문 14~16px, 보조 정보 12~13px, 공통 요약 수치 24~36px 등 역할별 글자 크기를 통일했다. 세 요약 카드의 수치 크기·정렬도 일치시켰다. 모바일 입력 필드는 16px를 유지한다.
- 개인 캘린더에서 `확인 중` 문구를 제거했다. 승인되지 않은 기록을 승인으로 바꾸지 않으며 거리·시간과 날짜 선택은 유지한다. 접근성 이름은 중립적인 `운동 기록`으로 표시한다.
- 공통 멤버 상세의 자기소개 영역을 제거했다. 저장된 자기소개 데이터는 삭제하지 않았다.
- 멤버 상세는 작은 프로필, 3열 요약, 캘린더만 표시한다. 화면 높이에 따라 여백·셀 높이를 조절하고 낮은 가로 화면에서는 프로필/요약과 캘린더를 좌우로 배치한다. 짧은 화면의 날짜별 보조 거리는 선택 상세에서 확인한다. 날짜 버튼은 최소 24px이고 극단적인 높이·텍스트 확대에서는 안전한 세로 스크롤을 허용한다.

## 검증

- 자동 테스트 122개, TypeScript, 변경 TS/TSX ESLint, diff 공백 검사 통과.
- 로그인 복귀 URL 정규화, 명시적 직접 링크 일회성 열기, 이전 해시 새로고침 시 닫힘, 버튼/해시 이벤트를 통한 재진입, history state·쿼리 보존, 이벤트 정리 검증.
- pending 기록의 수치 보존과 중복/삭제 문구 제거 검증.
- 로컬 예시 내 정보 바로가기 → URL 해시 제거 → 실제 브라우저 reload → 닫힌 기본 화면 확인. 운영 검수 브라우저는 로그아웃 상태여서 신규 OAuth 로그인 자체는 수행하지 않았다. 로그인 버튼의 복귀 주소와 로그인 서버의 정규화 경로는 검사했다.
- 6주 캘린더를 320×480, 320×568, 390×844, 612×998, 568×320, 844×390에서 검수했다. 모두 대화상자와 내부 패널의 clientHeight=scrollHeight, 가로 넘침 없음. 낮은 화면의 거리 단위가 중간에 끊기지 않게 처리했다.
- 로컬 320px 및 배포 후보 612px에서 헤더 3개 요소의 computed font-family/font-size/font-weight/color/line-height 일치 확인.
- 후보 및 운영 도메인의 실제 멤버 상세에서 자기소개·확인 중 문구 없음, 한 화면 배치 확인. 운영 새로고침 후 메인 화면 복귀 확인. 실제 댓글·회원 기록·프로필을 등록/수정/삭제하지 않았다.
- 운영 빌드, 비공개 저장소 읽기·쓰기/익명 거절 검사, 기록 스키마, 합성 이미지의 실제 OCR 검사 통과. 테스트용 임시 저장 객체는 정리됐다.
