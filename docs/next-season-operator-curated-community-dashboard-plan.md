# 스내사 다음 시즌 기획 — 100번의 아침, 20개의 이야기

> 참가자 로그인 없이 운영자 한 명이 인증과 상품 배너를 등록하고, 공개 대시보드에서는 경쟁 대신 서로의 아침과 일을 편안하게 만나는 운영자 큐레이션형 시즌 기획 0.1

## 1. 이번 변경의 핵심

이전 안의 개인 앱·게임 보상 성격을 모두 덜어낸다.

| 항목 | 이전 안 | 이번 안 |
|---|---|---|
| 참가자 로그인 | 카카오 로그인 또는 개인 화면 | 완전히 제거 |
| 인증 등록 | 참가자 직접 제출 중심 | 운영자가 외부로 받은 자료를 일괄 등록 |
| 메인 콘텐츠 | 오늘 인증 현황 | 참가자 상품·서비스를 소개하는 큰 메인 배너 |
| 보상 | 잎사귀·인장·뱃지 | 없음 |
| 동기부여 | 개인 수집·성장 | 함께 켜지는 풍경, 매일 바뀌는 크루 이야기, 공동 회고 |
| 경쟁 | 순위·비교를 최소화 | 순위·점수·목표 부족분을 만들지 않음 |
| 공개 기록 | 완료 상태와 개인 상세 | 동일하되 참가자 동의를 받은 항목만 공개 |

새 시즌은 `운동 관리 앱`이 아니라 **매일 한 명의 일을 알아가고, 여러 사람의 아침이 하나의 풍경으로 모이는 공개 크루 기록장**이다.

## 2. 한 문장 정의

**오전 8시 전 3km를 각자의 속도로 완료하고, 운영자가 기록을 반영하면 캐릭터의 불빛이 켜지며, 매일 한 명의 상품과 이야기를 함께 보는 100일 대시보드.**

## 3. 제품 원칙

1. 더 빠르거나 더 멀리 간 사람이 더 큰 보상을 얻지 않는다.
2. 모든 유효 인증은 풍경에 같은 크기의 변화를 만든다.
3. 상품 메인 배너 순서는 러닝 성과와 완전히 분리한다.
4. 미완료를 실패나 결석으로 표현하지 않는다.
5. 전날 기록을 오늘의 부담으로 끌고 오지 않는다.
6. 참가자는 로그인하거나 데이터를 편집하지 않는다.
7. 운영자는 `작성 → 검증 → 미리보기 → 게시 → 되돌리기` 흐름으로 안전하게 일괄 처리한다.
8. 공개 화면은 읽기 전용이며, 공개하기로 합의한 최소 정보만 전달한다.

## 4. 역할과 운영 모델

### 참가자

- 기존 단체 대화방 등 정해진 외부 채널로 인증 자료를 보낸다.
- 대시보드는 로그인 없이 본다.
- 자신의 캐릭터를 눌러 공개 기록을 확인할 수 있다.
- 배너에 사용할 상품·서비스 정보와 이미지의 공개 범위에 사전 동의한다.
- 대시보드에서 기록이나 배너를 직접 수정하지 않는다.

### 운영자 1명

- 관리자 계정으로만 로그인한다.
- 인증 이미지 여러 장을 한 번에 올리고 인식 결과를 검토해 게시한다.
- 직접 입력이나 표 붙여넣기로 기록을 보완한다.
- 시즌 전에 참가자 배너를 일괄 등록하고 100일 노출 일정을 확정한다.
- 게시 전 미리보기와 게시 후 되돌리기를 사용한다.

### 공개 방문자

- 별도 계정 없이 오늘의 배너와 공동 풍경을 본다.
- 캐릭터를 누르면 공개가 허용된 거리와 운동시간을 본다.
- 어떤 정보도 작성하거나 수정할 수 없다.

## 5. 공통 대시보드 정보 구조

```text
┌──────────────────────────────────────────┐
│  100번의 아침 · DAY 24 / 100            │
├──────────────────────────────────────────┤
│                                          │
│          오늘의 크루 상품 배너           │
│      이미지 · 이야기 · 외부 링크         │
│                                          │
├──────────────────────────────────────────┤
│  오늘 14개의 아침이 켜졌어요             │
│  완료 수에 따라 자연스럽게 달라지는 풍경 │
├──────────────────────────────────────────┤
│  고정된 참가자 캐릭터 그리드             │
│  완료 = 따뜻한 불빛 / 기록 없음 = 기본   │
├──────────────────────────────────────────┤
│  100일 공동 기록띠 · 지난 크루 이야기    │
└──────────────────────────────────────────┘
```

### 5.1 시즌 헤더

- 시즌명
- `DAY 24 / 100`
- 오늘 날짜
- 마지막 운영자 반영 시각

퍼센트 진행률, 남은 미완료 인원, 목표 부족분은 표시하지 않는다. 날짜 진행은 누구도 실패할 수 없는 공통 시간으로만 보여준다.

### 5.2 큰 메인 배너 — 오늘의 크루

대시보드에서 가장 큰 영역이다.

```text
오늘의 크루

[상품·서비스 대표 이미지]

BONANZA COFFEE KOREA
오늘의 러닝 뒤, 좋은 커피 한 잔
신*희님의 아침과 일을 소개합니다.

[이야기 더 보기 ↗]
```

배너 구성:

- 상품·서비스 대표 이미지 1장
- 브랜드 또는 프로젝트명
- 짧은 제목 1줄
- 소개문 1~2문장
- 참가자의 한마디 1문장
- 외부 링크 버튼 1개
- `오늘의 크루 상품` 식별 문구
- 필요한 경우 `광고`, `협찬`, `제휴` 표시

자동 재생 영상과 빠르게 넘어가는 캐러셀은 사용하지 않는다. 하루 동안 한 명의 이야기를 충분히 볼 수 있게 한다.

### 5.3 오늘의 공동 풍경

```text
오늘 14개의 아침이 켜졌어요.
각자의 속도로 같은 아침을 지나고 있어요.
```

- 완료가 등록될 때마다 창문 불빛, 햇살, 새, 이슬 같은 환경 요소가 조용히 하나 늘어난다.
- `14/20`, `6명 남음`, `70% 달성`처럼 부족분을 계산하지 않는다.
- 정확한 보상 단계나 잠금 해제 조건을 표시하지 않는다.
- 완료가 적은 날은 `실패한 풍경`이 아니라 `고요한 아침`으로 표현한다.
- 풍경은 자정에 기본 상태로 돌아가며 다음 날을 새로 시작한다.

### 5.4 참가자 캐릭터 그리드

모든 캐릭터는 매일 같은 자리를 유지한다.

| 상태 | 공개 표현 |
|---|---|
| 오전 8시 전 3km 완료 | 따뜻한 해무리, 작은 체크, 짧은 기지개 |
| 아직 기록 없음 | 평온한 기본 모습 |

- 완료 순서, 거리, 운동시간, 스트릭으로 재정렬하지 않는다.
- 미완료 캐릭터를 흐리게 만들거나 별도 구역에 모으지 않는다.
- `실패`, `미달`, `결석`, 빨간 X를 사용하지 않는다.
- 이름은 기존처럼 가운데 글자를 `*`로 가린다.

### 5.5 캐릭터 클릭 창

로그인이 없으므로 이 창의 내용은 누구에게나 공개되는 읽기 전용 정보다.

```text
신*희
오늘 오전 인증 완료

오늘 3.24km · 운동시간 31분

[이 크루의 상품 보기]
```

공개 권장 항목:

- 오늘 완료 여부
- 오늘 오전 유효 거리
- 운동 소요시간
- 완료일만 점으로 남긴 100일 기록
- 완료일을 누르면 표시되는 해당 날짜의 거리와 운동 소요시간
- 해당 참가자의 상품·서비스 작은 카드

공개하지 않는 항목:

- 정확한 시작·종료 시각
- GPS 경로와 좌표
- 인증 원본 이미지와 파일명
- 이미지 EXIF
- 앱명
- 운영자 메모와 수정 이력
- 미완료 사유

### 5.6 100일 공동 기록띠

- 하루마다 한 칸이 생기는 100칸 가로 기록이다.
- 그날 모인 인증 수에 따라 색의 농도만 달라진다.
- 목표선, 성공·실패 칸, 사람별 순위가 없다.
- 칸을 누르면 그날의 공동 문장과 등장했던 상품 배너를 본다.

## 6. 상품 배너의 공정한 순환

예상 참가자 20명과 100일 시즌은 정확히 다섯 번의 순환을 만들 수 있다.

### 기본 규칙

- 모든 참가자는 100일 동안 정확히 5일씩 메인 배너에 등장한다.
- 100일을 20일짜리 5개 순환으로 나눈다.
- 각 순환에서 모든 참가자가 한 번씩 등장한다.
- 같은 참가자의 노출 간격은 약 20일로 유지한다.
- 주말 노출 횟수 차이는 최대 1회로 맞춘다.
- 시즌 초·중·후반에 모두 노출된다.
- 인증률, 거리, 스트릭, 운영자 선호, 클릭 수, 판매량으로 순서를 바꾸지 않는다.
- 일정 변경이 필요하면 노출을 추가하지 않고 날짜를 서로 교환한다.

### 다섯 번의 이야기 예시

한 개의 기본 배너를 다섯 번 반복해도 된다. 콘텐츠를 나누고 싶다면 다음 순서를 사용한다.

1. 나와 일을 소개합니다.
2. 이 일을 시작한 이유를 이야기합니다.
3. 대표 상품·서비스를 소개합니다.
4. 크루에게 추천하고 싶은 활용법을 전합니다.
5. 100일을 함께한 감사 인사를 전합니다.

다섯 가지 콘텐츠 변형은 후속 선택 사항이다. 첫 구현에서는 참가자마다 기본 배너 한 개만 있어도 충분하다.

### 상품이 없는 참가자

배너 순번을 빼앗지 않는다. 다음 중 하나로 같은 크기의 기본 카드를 제공한다.

- 요즘 하고 있는 프로젝트
- 크루에게 소개하고 싶은 활동
- 아침 루틴에 관한 한마디
- 좋아하는 장소나 도구
- 운영자가 준비한 `오늘의 크루 이야기`

### 배너가 경쟁이 되지 않도록 하는 규칙

- 공개 조회수, 좋아요, 클릭 수, 판매 순위를 제공하지 않는다.
- 인기순 배너 목록을 만들지 않는다.
- 지난 배너 아카이브는 날짜순 또는 참가자 고정 순서로만 정렬한다.
- 배너 노출은 그날의 러닝 완료 여부와 무관하게 보장한다.
- 다른 참가자의 배너보다 더 큰 형식이나 더 긴 노출을 구매할 수 없다.

## 7. 경쟁 없는 공동 플레이

### 핵심 루프

```text
저녁의 공동 준비 문구
→ 아침 3km
→ 외부 채널로 인증 전달
→ 운영자 일괄 등록
→ 캐릭터 불빛과 공동 풍경 변화
→ 오늘의 크루 이야기 발견
→ 다음 날 새 장면
```

### 7.1 매일 찾아올 이유

- 오늘 누구의 상품과 이야기가 등장했는지 궁금하다.
- 운영자가 기록을 반영한 뒤 자신의 캐릭터 불빛을 확인한다.
- 오늘 함께한 아침들이 만든 풍경을 본다.
- 어제와 다른 한 문장과 계절색을 만난다.

보상이나 수집품이 아니라 **호기심, 존재감, 소속감, 반복되는 의식**이 방문 동기가 된다.

### 7.2 시간대별 공동 문구

개인 저장 기능 없이 모두에게 같은 한 가지 행동만 제안한다.

저녁:

> 내일의 3km는 오늘 신발을 꺼내 놓는 데서 시작해요.

오전 5시~7시 15분:

> 좋은 아침이에요. 오늘도 3km만, 각자의 속도로.

오전 7시 15분~7시 40분:

> 아침 마을이 하나씩 깨어나는 중이에요. 걷기부터 천천히 시작해요.

오전 7시 40분 이후:

> 시간이 빠듯하다면 8시에 맞추려고 속도를 올리지 마세요. 안전한 오늘의 기록도 남길 수 있어요.

오전 8시 이후:

> 오늘 모인 아침을 그대로 남겨둘게요. 다음 아침은 다시 새로 시작됩니다.

### 7.3 등록 직후의 변화

운영자가 유효 인증을 게시하면 해당 캐릭터가 조용히 바뀐다.

1. 창문 또는 등불이 켜진다.
2. 캐릭터가 한 번 기지개를 켠다.
3. 공동 풍경에 햇살이나 새가 하나 더해진다.

이름을 호명하는 완료 피드와 등록 순서를 만들지 않는다.

- `오늘의 불빛이 하나 더 켜졌어요.`
- `한 사람의 아침이 마을에 도착했어요.`
- `각자의 속도로 아침이 이어지고 있어요.`

### 7.4 주간 공동 회고

사람별 표나 순위 없이 지난 일곱 날을 한 장의 풍경으로 정리한다.

```text
지난주의 아침

오전 8시 전 3km · 68번
7일 모두 누군가의 불빛이 켜졌어요.

이번 주에도 3km만, 각자의 속도로.
```

사용하지 않는 표현:

- `지난주보다 하락`
- `목표에 8회 부족`
- `가장 많이 달린 사람`
- `꼴찌 요일`
- `완료율이 저조합니다`

### 7.5 누락과 복귀

- 매일 자정 모든 캐릭터는 동일한 기본 상태로 돌아간다.
- 전날의 빈칸이나 끊어진 스트릭을 오늘 카드에 표시하지 않는다.
- 놓친 거리를 다음 날 보충하도록 요구하지 않는다.
- 과거 달력에는 완료한 날만 점으로 표시하고 나머지는 빈칸으로 둔다.
- 다시 등록된 날도 다른 완료와 정확히 같은 불빛을 켠다.

복귀 문구:

- `어제와 관계없이 오늘의 3km는 새 기록입니다.`
- `쉬었다가 돌아온 아침도 같은 한 번입니다.`
- `놓친 거리를 갚지 않아도 오늘의 3km는 온전합니다.`

복귀를 별도의 뱃지나 추가 보상으로 만들지 않는다.

### 7.6 100일의 변화

20일마다 배경의 계절색과 공동 문장만 바뀐다. 특정 달성 수를 다음 장면의 해금 조건으로 삼지 않는다.

1. 1~20일: 문 앞의 신발
2. 21~40일: 같은 길의 아침
3. 41~60일: 깨어나는 마을
4. 61~80일: 스스로 이어지는 길
5. 81~100일: 남겨진 아침

시즌 종료 화면:

```text
우리는 100일 동안
서로 다른 속도로 같은 아침을 지나고,
20개의 일과 이야기를 함께 보았습니다.
```

순위표 대신 100일 공동 기록띠, 전체 아침 수, 크루 이야기 아카이브만 남긴다.

## 8. 관리자 일괄 인증 등록

현재 관리자 화면에는 최대 20장의 인증 이미지를 한 번에 인식하는 OCR 흐름이 이미 있다. 이를 참가자 직접 업로드 대신 **운영자 전용 기본 입력 방식**으로 정리한다.

### 하루 운영 흐름

1. 운영자가 외부 채널에서 인증 이미지를 모은다.
2. 오늘 날짜를 선택하고 이미지 여러 장을 드래그한다.
3. OCR이 참가자, 거리, 날짜, 운동시간을 제안한다.
4. 20명이 고정된 검토 표에서 결과를 확인하고 보완한다.
5. 서버 검증 결과와 기존값 대비 변경점을 미리 본다.
6. 한 번에 게시한다.
7. 게시 영수증과 되돌리기 버튼을 확인한다.
8. 공개 대시보드 캐시가 갱신된다.

### 표 붙여넣기·CSV 입력

이미지가 없거나 OCR이 어려운 경우를 위해 같은 검토 표에 직접 붙여넣을 수 있다.

```text
활동 날짜 | 참가자 | 거리 | 운동시간 | 오전 인증 확인 | 이미지
```

- 필수: 참가자, 활동 날짜, 거리, 오전 인증 확인
- 선택: 운동 소요시간, 정확한 시각, 앱명, 인증 이미지
- 여러 기록은 참가자와 날짜별로 합산한다.
- 빈 셀은 삭제가 아니라 `변경 없음`으로 처리한다.
- 중복, 시즌 밖 날짜, 거리 형식, 참가자 불일치를 게시 전에 표시한다.

### 안전한 일괄 게시

- 게시 전에 신규·수정·변경 없음·오류 건수를 보여준다.
- 각 행에서 기존값과 새 값을 비교한다.
- 정상 행과 오류 행을 명확히 나누고 `정상 19건 게시 · 오류 1건 초안 보류`처럼 게시 결과를 미리 보여준다.
- 운영자가 부분 게시를 명시적으로 확인하면 정상 행만 게시하고 오류 행은 초안에 남긴다. 조용한 부분 반영은 허용하지 않는다.
- 각 게시에 `배치 ID`를 부여한다.
- 직전 배치를 되돌릴 수 있게 하되 물리 삭제 대신 역변경 이력을 남긴다.
- 운영자가 과거 날짜를 입력할 수 있으며 사유 입력은 요구하지 않는다.
- 과거 기록 수정은 오늘의 완료 애니메이션을 다시 재생하지 않는다.

## 9. 관리자 배너 일괄 등록

배너는 시즌 시작 전에 최대한 준비해 매일 운영 부담을 만들지 않는다.

### 등록 방식

1. 운영자가 배너 CSV 템플릿을 내려받는다.
2. 참가자, 제목, 소개, 링크, 이미지 파일명 등을 채운다.
3. CSV와 이미지 묶음을 한 번에 업로드한다.
4. 시스템이 20명 × 최대 5개 배너를 참가자와 연결한다.
5. 100일 공정 순환 일정을 자동 생성한다.
6. 데스크톱·모바일 미리보기에서 잘림과 문구를 확인한다.
7. 초안 전체를 일괄 예약한다.

### 배너 필드

```text
participant_id
brand_name
headline
description
member_quote
image
image_alt
target_url
button_label
disclosure_type
consent_version
cycle_number
status
```

상태:

```text
draft → scheduled → published → expired
                  ↘ paused
```

### 링크와 이미지 정책

- 연결 URL은 `https`만 허용한다.
- 단축 URL, 임의 스크립트, HTML 삽입을 허용하지 않는다.
- 외부 링크는 새 탭으로 열고 안전한 `rel` 속성을 사용한다.
- 이미지의 실제 형식을 검사하고 서버에서 다시 인코딩한다.
- EXIF를 제거하고 안전한 파일명으로 저장한다.
- 데스크톱과 모바일 비율을 각각 미리 본다.
- 만료되거나 중지된 배너는 기본 시즌 배너로 자동 대체한다.

## 10. 로그인 제거 후 정보 구조

### 남기는 로그인

- 관리자 로그인 1개만 유지한다.
- 공개 회원가입과 참가자 로그인은 제공하지 않는다.

### 공개 읽기 데이터

공통 대시보드 초기 응답:

```text
participant_id
masked_name
character_id
today_completed
featured_banner
shared_day_summary
```

캐릭터 클릭 시 공개 상세 응답:

```text
today_valid_distance
today_duration
completion_calendar
selected_day_distance
selected_day_duration
public_product_summary
```

### 관리자 전용 데이터

```text
exact_start_at
exact_end_at
individual_activities
proof_image
source_app
admin_note
batch_id
audit_log
banner_consent
```

공개 API가 관리자 테이블 전체를 그대로 반환한 뒤 화면에서 숨기는 방식은 사용하지 않는다. 공개용 응답에서 허용한 필드만 별도로 만든다.

### 로그인 제거에 따른 한계

- 개인별 알림을 보낼 수 없다.
- 본인만 보는 비공개 화면을 만들 수 없다.
- 전날 계획이나 몸 상태를 개인별로 저장할 수 없다.
- 캐릭터 클릭 창의 정보는 사실상 인터넷 공개 정보다.

따라서 개인 동기 기능 대신 공동 화면의 시간대 문구와 외부 단체 대화방의 하루 한 번 공유 카드로 보완한다.

## 11. 인증 규칙

현재 기획의 판정은 다음을 기본으로 한다.

```text
한국시간 오전 07:59:59까지 끝난 유효 활동의 당일 합산 거리 >= 3.00km
→ 오늘 오전 인증 완료
```

- 여러 활동은 같은 참가자와 활동 날짜를 기준으로 합산한다.
- 3km를 초과해도 공동 풍경에는 같은 불빛 하나만 더한다.
- 빠른 속도나 긴 거리에 추가 효과를 주지 않는다.
- 인증 자료는 당일 23:59:59까지 외부 채널로 전달할 수 있다.
- 운영자는 마감 후에도 과거 날짜 기록을 넣을 수 있고 사유는 요구하지 않는다.
- 오전 8시 이후 활동은 기록에는 보존하되 오늘 오전 완료로 바꾸지 않는다.
- 정확한 시작·종료 시각이 없다면 운영자가 증빙을 보고 `오전 인증 확인`을 명시한다.

## 12. 뱃지 없이 동기부여하는 원칙

### 제공하는 것

- 완료 등록 직후 캐릭터의 작은 변화
- 인증 수에 따라 달라지는 그날의 공동 풍경
- 매일 달라지는 한 명의 상품과 이야기
- 시간대별로 한 가지 행동만 권하는 공동 문구
- 비교 없는 주간 공동 회고
- 달력에 따라 자연스럽게 바뀌는 계절 장면
- 누락을 벌하지 않고 다음 날 새로 시작하는 복귀 경험

### 만들지 않는 것

- 뱃지, 도감, 수집품, 레벨
- 코인, 상점, 교환, 선물
- 순위, 퍼센트 경쟁, 목표 부족분
- 스트릭 상실 경고
- 완료 순서 피드
- 인기 상품 순위와 공개 클릭 수
- 달성해야만 열리는 배경
- 미완료자 전용 독촉

이 플레이의 보상은 소유하는 아이템이 아니라 **내가 오늘 이 풍경 안에 함께 있다는 확인**이다.

## 13. 톤앤매너

### 콘셉트

**포근한 아침 매거진과 조용히 깨어나는 크루 마을의 결합.**

- 상품 배너는 에디토리얼 사진과 짧은 이야기로 구성한다.
- 캐릭터 영역은 서로 다른 사람들이 한 공간에 머무는 마을처럼 보이게 한다.
- 게임 UI보다 잡지, 동네 게시판, 아침 일기장에 가깝게 만든다.

### 색과 움직임

- 바탕: 따뜻한 크림, 옅은 새벽 라벤더
- 기본 텍스트: 짙은 숲색
- 완료 빛: 살구색과 부드러운 노랑
- 링크 포인트: 차분한 초록
- 애니메이션: 2초 이내 한 번만 재생
- 자동 재생 영상, 반짝이는 보상, 폭죽 효과 없음

### 카피 원칙

사용할 표현:

- `오늘도 3km만, 각자의 속도로.`
- `오늘의 불빛이 하나 더 켜졌어요.`
- `오늘 모인 아침을 그대로 남겨둘게요.`
- `어제와 관계없이 오늘은 새 기록입니다.`
- `서로 다른 속도로 같은 아침을 지납니다.`

피할 표현:

- `마감 임박`
- `아직 6명 남았어요`
- `모두가 기다리고 있어요`
- `스트릭이 끊겼습니다`
- `지난주보다 저조합니다`
- `완벽한 100일`

## 14. 경량화 원칙

큰 배너를 넣더라도 첫 화면을 무겁게 만들지 않는다.

- 메인 배너 이미지 1장만 우선 로드한다.
- 모바일·데스크톱 반응형 WebP/AVIF를 생성한다.
- 배너 영역에 고정 비율을 두어 화면 밀림을 막는다.
- 지난 배너 이미지는 화면에 들어올 때만 불러온다.
- GIF, 자동 재생 영상, 제3자 광고 스크립트를 넣지 않는다.
- 20명의 오늘 완료 상태는 한 번의 작은 응답으로 전달한다.
- 100일 개인 기록은 첫 화면에 싣지 않고 캐릭터 클릭 시 조회한다.
- 실시간 웹소켓 대신 관리자 게시 직후 캐시만 갱신한다.
- 공개 페이지 번들에 관리자 업로드와 인증 코드를 포함하지 않는다.
- 원본 인증 이미지는 공개 화면에서 불러오지 않는다.

## 15. 기존 코드 활용 방향

현재 로컬 코드에는 이미 다음 기반이 있다.

- `DashboardClient`의 상단 슬롯
- `MemberServiceAdPocBanner`와 멤버 서비스 배너 POC 페이지
- 기존 캐릭터 그리드와 개인 팝업
- 최대 20장 이미지 일괄 OCR
- 관리자 기록 수정 흐름
- 공개 대시보드 데이터 조회와 갱신

새로 필요한 핵심은 다음 정도다.

- 정적 POC 배너를 데이터 기반 예약 배너로 변경
- 배너 관리자와 100일 공정 순환 일정
- 인증 배치 미리보기·게시·되돌리기
- 새 시즌에서 참가자 로그인 화면과 참가자 쓰기 경로 비활성화
- 공개 요약과 클릭 상세 데이터 분리
- 공동 풍경과 100일 기록띠

기존 대시보드 컴포넌트를 복사하지 않고 시즌 설정, 표시 필드, 색상 토큰을 바꾸는 방식으로 재사용한다.

## 16. 안전한 전환 순서

### 1단계 — 이전 시즌 동결

- 이전 시즌 기록 쓰기 차단 확인
- 이전 시즌 화면 관리자 전용 유지
- 새 시즌 날짜와 데이터 분리

### 2단계 — 권한 단순화

- 새 시즌의 참가자 로그인·회원가입 화면과 쓰기 권한 비활성화
- 이전 시즌 동결 기록과 관리자 조회에 필요한 과거 계정·사용자 식별 데이터는 보존
- 새 시즌의 참가자 쓰기 API 비활성화
- 관리자 로그인과 서버 권한 검사 유지
- 공개 읽기 API의 허용 필드 확정

### 3단계 — 배너 정식화

- 기존 로컬 POC를 동적 배너로 전환
- 배너 일괄 등록과 미리보기
- 100일 공정 순환 일정 생성
- 공개 동의와 만료 처리

### 4단계 — 운영자 인증 일괄 등록

- 기존 OCR 흐름 재사용
- 20명 고정 검토 표
- 변경점 미리보기와 배치 게시
- 되돌리기와 수정 이력

### 5단계 — 공개 대시보드

- 큰 상품 배너
- 완료 상태만 보이는 캐릭터 그리드
- 캐릭터 클릭 공개 상세
- 경쟁 없는 공동 풍경
- 100일 공동 기록띠

### 6단계 — 후속 콘텐츠

- 주간 공동 회고
- 지난 배너 아카이브
- 단체 대화방 공유용 `오늘의 풍경 카드`
- 20일 단위 계절 장면

모든 구현은 로컬에서 검증하며, 별도 승인 전에는 푸시·배포·프로덕션 데이터 변경을 하지 않는다.

## 17. 운영 안전장치

- 관리자 계정은 강한 인증과 복구 수단을 사용한다.
- 배너·기록 게시 전에 변경점 미리보기를 제공한다.
- 각 배치에 ID를 부여하고 게시·수정·되돌리기 이력을 남긴다.
- 배너 링크와 이미지 변경 이력을 보존한다.
- 기록과 배너를 바로 물리 삭제하지 않는다.
- 여러 탭에서 오래된 화면이 최신 데이터를 덮지 않도록 버전 충돌을 검사한다.
- 공개 동의 철회 시 배너와 기록을 즉시 비공개 처리할 수 있게 한다.
- 배너 이미지의 사용 권리와 외부 링크를 게시 전에 확인한다.

## 18. 성공 지표

경쟁을 만들지 않는 운영·루틴 지표를 사용한다.

- 오전 인증이 하나 이상 있었던 날의 수
- 전체 오전 인증 횟수
- 기록이 없던 다음 날 다시 인증된 횟수
- 7일·30일 단위의 활동 유지율
- 대시보드 일별 방문 수의 익명 집계
- 상품 배너 노출 일정의 균등성
- 관리자 일일 인증 처리시간
- OCR 후 수동 보정 비율
- 배치 게시 후 되돌리기 횟수
- 시즌 중간·종료 후 참가자의 소속감 설문

첫 구현에서는 배너 클릭 수를 집계하지 않는다. 외부 링크가 정상적으로 열리는지만 운영 점검한다.

## 19. 확정이 필요한 네 가지

### 1. 상품 배너의 이름 공개 범위

권장안은 참가자 이름은 `신*희`처럼 가리고 브랜드명과 승인한 외부 링크만 공개하는 것이다. 외부 링크가 실명을 드러낼 수 있으므로 별도 공개 동의를 받는다.

### 2. 상품이 없는 참가자의 배너

권장안은 배너 순번을 유지하고 프로젝트, 활동, 아침 한마디 중 하나를 같은 형식으로 소개하는 것이다.

### 3. 공개 개인 창의 거리 범위

권장안은 오늘 또는 선택한 날짜의 유효 거리와 운동 소요시간만 공개하는 것이다. 시즌 누적 거리와 스트릭은 공개하지 않고, 정확한 시각과 원본 자료는 관리자만 본다.

### 4. 배너 외부 링크

권장안은 참가자당 승인된 `https` 링크 하나만 허용하고, 인스타그램·스마트스토어·공식 사이트 중 하나를 선택하게 하는 것이다.

## 20. 최종 추천

새 시즌의 동기부여는 무언가를 얻거나 남을 이기는 데서 나오지 않는다.

- 오늘 내 캐릭터의 불빛이 켜진다.
- 다른 사람들의 불빛과 함께 한 장면을 만든다.
- 매일 한 명의 일과 상품을 새롭게 알게 된다.
- 하루를 놓쳐도 다음 날 같은 자리에서 다시 시작한다.
- 100일 뒤에는 순위가 아니라 함께 만든 풍경과 20개의 이야기가 남는다.

이 구조라면 개인 로그인과 무거운 게임 시스템 없이도 기존 대시보드를 매일 방문할 이유가 생기고, 러닝과 크루의 관계가 경쟁이 아닌 관심과 연결로 남는다.
