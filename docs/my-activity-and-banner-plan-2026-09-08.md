# 내 활동 재기획 · 배너 검수

2026-09-08 최초 기획 기록. 이후 내 활동 화면·권한·API를 구현했고 배너 날씨 표시는 제거했다. 최신 구현·검증·운영 상태는 [배포 기록](./my-activity-release-2026-09-08.md)을 따른다. 아래 내용은 기획 당시의 기준과 검수 이력이다.

## 편집 위치의 원칙

- 상단 본인 이름 클릭 → `내 활동`. 공개 멤버 상세는 본인도 읽기 전용이다.
- 멤버 상세에는 사진 변경, 기본 이미지로 변경, 이름 수정, 파일 입력을 노출하지 않는다. 인증 캘린더·공개 기록·자기소개 열람은 유지한다.
- 본인 정보와 기록을 편집하는 진입점은 내 활동으로 통일한다. 기존 댓글·목표·문의 등 본인 작성 내용의 수정/취소가 제공되는 경우에도 내 활동에서 해당 관리 화면으로 연결한다. 공개 목록에는 읽기 기능을 유지한다.
- 운영자 어드민은 별도 관리 권한을 유지한다.
- 새 편집 화면이 준비되기 전에 기존 사진 편집만 먼저 없애 사용자가 편집할 곳을 잃게 하지 않는다. 이동은 같은 변경 묶음으로 구현한다.
- 메뉴를 숨기는 것은 권한 검사가 아니다. 서버에서 세션과 participant ID를 대조하고 본인 소유 항목만 수정하도록 한다.

## 내 활동: 세 개의 주 메뉴

첫 화면에는 사진·이름, 오늘의 상태, 세 개의 메뉴만 배치한다. 각 메뉴는 같은 팝업 안에서 전환하고 겹치는 팝업을 만들지 않는다. 하위 화면은 뒤로 가기로 요약으로 돌아온다.

### 1. 프로필 관리

- 프로필 사진: 사진 선택, 미리보기, 저장, 기본 사진으로 변경.
- 이름: `표시 이름` 입력, 저장. 카카오 인증 정보와 표시 이름은 구분하고 기록 연결에는 변하지 않는 계정/참가자 ID를 사용한다.
- 계정 연결 상태는 읽기 전용으로 표시한다. 이름 변경으로 다른 멤버의 기록을 연결하지 않는다.
- 저장 성공 후 헤더·내 활동·공개 멤버 카드에 같은 값이 반영되도록 캐시를 갱신한다. 실패하면 입력은 유지하고 재시도할 수 있게 한다.
- 기존 작성 내용의 관리는 필요 시 보조 링크로 연결하고 첫 화면을 복잡하게 만들지 않는다.

### 2. 인증샷 업로드

- 기기 사진 선택 → 업로드 진행률 → 이미지 식별 → 날짜·거리·시간 확인 → `인증 제출` → `확인 중`.
- 식별한 거리와 시간은 승인 전에도 본인 기록에 보인다. 확인 중인 기록은 공식 인증일·공식 인증률에 포함하지 않는다.
- 인식되지 않은 값은 0으로 채우지 않고 `확인 필요`로 표시한다. 사용자가 보완한 값과 OCR 결과를 구분해 검수한다.
- 업로드 실패·식별 실패·중복 제출·미래 날짜를 각각 처리한다. 더블클릭이나 재시도가 중복 기록을 만들지 않게 한다.
- 촬영 이미지 크기·포맷을 서버에서 검증하고 OCR 정확도를 해치지 않는 범위에서 크기를 줄인다. 불필요한 위치 메타데이터는 제거한다.
- 원본 인증샷은 기본 비공개로 본인과 권한 있는 운영자만 열람한다. 공통 대시보드에는 공개 정책에 맞는 기록 값만 보낸다.
- 현재 `/api/me/records/analyze`와 `/api/me/records`의 POST는 403이다. 개인 인증 등록을 새로 허용할 때 서버 소유권 검증·비공개 업로드·검수 흐름이 함께 필요하다. 기존 관리자 API를 개인에게 그대로 열지 않는다.

### 3. 누적 활동

- 총 인증일, 누적 거리, 누적 시간을 먼저 표시한다.
- `거리 / 시간 / 인증일` 선택과 `주 / 월 / 전체` 기간 전환을 제공한다.
- 기존 개인 기록 API·SVG 그래프 집계를 재사용하되 흰색·연회색·파란색으로 톤을 통일한다. 무거운 차트 라이브러리를 추가하지 않는다.
- 공식 승인 기록을 기본 집계로 사용한다. 시즌 전 기록과 확인 중 기록은 별도 상태로 구분한다.
- 그래프 아래 인증 캘린더에서 날짜별 거리·시간과 검수 상태를 확인한다.

## 팝업 UX와 성능

- 데스크톱은 상단 계정에 연결된 요약 팝업, 모바일은 하단 시트. 업로드·그래프 상세는 같은 패널을 확장한다.
- 내용 조회를 기다리지 않고 팝업 틀과 닫기 버튼부터 연다. 닫기·바깥 영역·Esc·포커스 복귀를 지원한다.
- 파일 업로드·분석 중에도 닫을 수 있다. 업로드 취소와 화면 닫기를 구분하며, 입력을 잃게 되는 경우에만 확인한다.
- 조회한 본인 요약은 계정별로 재사용하고 백그라운드에서 갱신한다. 로그아웃/계정 변경 시 캐시를 비운다. 늦게 도착한 이전 계정 응답은 버린다.
- 업로드·그래프 구현은 선택한 메뉴를 열 때 불러온다. 홈 진입에서 세 메뉴의 무거운 작업을 한꺼번에 실행하지 않는다.

## 배너 환경 규칙

- 인증률은 표시 러너 수(0~5명)를 결정한다. 날씨 때문에 공식 인증 수치나 달성률을 바꾸지 않는다.
- 시간대는 빛과 하늘 색을 결정하고 현재의 8초 색 전환을 유지한다.
- 날씨는 구름·눈·비 등 배경 표현을 결정한다. 계절/기온은 나무·적설·러너 의상을 결정한다. 폭설/강한 비에서는 움직임을 더 제한하는 연출을 검토한다.
- 사용자가 서울 강남구 공통 실제 날씨 연동을 선택했다. 대표 좌표 37.5172, 127.0473을 서버에 고정했고 개인 위치 권한·좌표를 사용하지 않는다.
- MET Norway Locationforecast 시간별 예보를 서버 API `/api/public/gangnam-weather`로 연결했다. 강남구 실측 관측값이나 실시간 적설량이라고 표시하지 않는다. 하단 날씨 출처에서 예보 기준 시각·단순화 설명·CC BY 4.0 링크를 제공한다.
- 서버는 공급자 Expires 이후에만 재조회하며 최소 1시간 캐시·동시 요청 합치기·If-Modified-Since·오류/429 재시도 간격을 적용한다. CDN 응답도 10분 캐시한다. 서버리스 인스턴스 캐시는 서로 독립이며 공유 CDN이 중복 호출을 추가로 줄인다.
- 클라이언트는 배경 이미지 이후에 조회하고 활성 화면에서 10분 간격으로 갱신한다. API 실패·오래된 예보는 메인 화면 오류로 전파하지 않는다. 제한 시간 이후 날씨 표현은 중립 상태로 돌아간다.
- 제공자에는 앱 식별용 User-Agent와 고정 좌표만 전달하고 사용자 쿠키·IP·위치를 전달하지 않는다. 유료 구독·키 발급·위치 권한 추가 없이 공개 API로 연결했다.
- 계절 이미지와 의상 프레임은 동일한 회색길 좌표를 유지해 별도 제작해야 한다. 이번 작업에 신규 계절 이미지는 포함하지 않는다.

## 이번 로컬 변경

- 인증 인원 변경 시 러너의 그림을 즉시 제거하지 않고 1.8초 opacity 전환으로 등장·퇴장한다.
- 한번 등장한 이미지 노드는 최대 5개까지 재사용한다. 최초 0%에서는 러너 이미지를 요청하지 않는다. 사라진 러너의 이동/발걸음은 정지한다.
- 이미지 파일·파일 용량은 바꾸지 않았고 프레임마다 실행하는 JavaScript나 React 갱신 루프를 추가하지 않았다.
- 작은 모바일의 밤 화면에서도 문구 뒤에 밝은 배경이 유지되도록 기존 그라데이션 범위를 조정했다.
- `각자의 속도로, 함께 나아가요.`를 포함한 배너 응원 문구를 모든 인증률 상태에서 제거했다. 인증률·인증 인원은 유지한다.
- 구름/안개/강수는 8초 투명도 전환, 비·눈은 최대 10개의 CSS 입자다. 번개 점멸이나 적설량 연출은 없다. 정지·화면 밖·팝업 상태에서 강수 입자도 정지한다.
- 미리보기에는 실제 강남구 예보와 별도로 맑음·구름·안개·비·눈 시뮬레이션을 제공한다. 시뮬레이션은 반드시 `연출 예시`로 표시한다. 기본값은 실제 예보와 서울 현재 시간이다.
- 회색길 64초 이동, 2.4초 발걸음, 화면 밖·팝업·모션 줄이기/데이터 절약 설정에 따른 제한을 유지한다.

## 검수 범위

- 단위/회귀 테스트 84개 통과. 수정 컴포넌트 ESLint와 TypeScript 검사 통과. 날씨 정상/실패/오래된 데이터/단위 오류/시간대/캐시/동시 요청/304/429 분기를 포함한다.
- 운영용 Next.js 빌드 성공. 배포는 수행하지 않았다.
- 390px 브라우저 뷰포트: 가로 넘침 없음, 배너 366×326px. 5명 모션 4초 표본 평균 8.3ms, P95 8.4ms, 50ms 초과 0회, 긴 작업 0회.
- 5→0명 변경: 이미지 노드가 전환 동안 유지되고 전환 후 opacity 0, visibility hidden, 러너 애니메이션 paused 확인.
- 320px: 배너 292×292px, 가로 넘침 없음. 밤 화면을 확인하고 가독성 그라데이션을 보완했다. 팝업 표시 14.5ms(두 프레임 기준), 팝업 중 5명의 경로 애니메이션 모두 paused.
- 날씨 적용 후 320px에서 러너 5명+눈 입자 10개: 평균 8.3ms, P95 9.3ms, 50ms 초과 0회, 긴 작업 0회(4초 표본). 팝업 14.1ms, 러너 5개·눈 입자 10개 모두 paused. 390px 밤·비 조건에도 가로 넘침 없음.
- 로컬 API HTTP 200, 249바이트 응답 확인. 2026-09-08 14시 KST 예보 기준 28.8°C/구름, 공급자 갱신 시각 14:21 KST. 특정 동네의 현장 관측값이 아니라 고정 좌표의 모델 예보다.
- 수치는 로컬 데스크톱 브라우저의 모바일 크기 재현 결과다. 실제 iPhone/Android, 느린 회선에서 측정한 것이 아니며 실제 사용자 INP/LCP를 대체하지 않는다. 신규 계절 이미지·옷 프레임은 아직 미구현이다.

운영 배포 없음. 내 활동 구현·계절 에셋 제작 후에는 해당 완성본을 다시 검수해야 한다.
