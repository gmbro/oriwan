# 스내사 다음 시즌 기획 — 2027로 가는 100번의 아침

> 2026년 9월 23일부터 12월 31일까지, 서울 강변 픽셀아트 속에서 서로를 추월하지 않고 함께 2027로 달려가는 운영자 큐레이션형 공개 대시보드 기획 0.1

## 1. 이번 요청의 반영 사항

| 요청 | 반영 방향 |
|---|---|
| 완료 문구 변경 | `오늘 아침, 20명 중 14명이 달렸어요.`로 통일 |
| 움직이는 러닝 배경 | 고정 러너와 다층 패럴랙스 배경을 사용하는 픽셀아트 사이드스크롤 |
| 참가자 이름 | 모든 공개 카드와 개인 창에 풀네임 표시, 관리자만 등록·수정 |
| 공통 화면 정보 | 인증 여부, 공통 목표, 일간·주간·월간·100일 인증률만 공개 |
| 개인 기록 | 캐릭터 클릭 창에서 선택한 날짜의 거리와 운동시간 표시 |
| 연말 톤앤매너 | 날짜가 지날수록 가을에서 겨울, 연말, 2027을 앞둔 불빛으로 변화 |
| 기존 운영 방식 | 참가자 로그인 없음, 운영자 일괄 인증·배너 등록 유지 |
| 경쟁 요소 | 순위, 뱃지, 코인, 개인 퍼센트, 최고·최저 비교 없음 |

## 2. 한 문장 정의

**같은 강변을 각자의 속도로 달리고, 100번의 아침을 지나 모두 함께 2027에 도착하는 공개 러닝 풍경.**

시즌 문구:

> 같은 강변을, 각자의 속도로.  
> 100번의 아침을 지나 2027로 갑니다.

## 3. 핵심 경험

1. 대시보드를 열면 픽셀아트 러너와 흐르는 서울 강변이 보인다.
2. 장면 속 큰 빌보드에서 오늘의 크루 상품과 이야기를 만난다.
3. 공통 목표 `오전 8시 전, 각자의 속도로 3km`를 확인한다.
4. 운영자가 기록을 반영하면 참가자 캐릭터가 `오늘 달렸어요` 상태로 바뀐다.
5. 공통 대시보드에는 개인 수치 대신 네 가지 공동 인증률만 남는다.
6. 날짜가 지날수록 장면이 가을에서 겨울로, 2026년에서 2027년으로 이동한다.
7. 12월 31일에는 순위표가 아니라 모두가 지나온 한 장의 공동 풍경이 남는다.

- 시즌 다음 아침: 2027년 1월 1일

## 6. 메인 픽셀아트 러닝 장면

### 콘셉트

첨부 이미지는 `가로형 서울 풍경`, `하단 러닝 트랙`, `러너와 응원하는 사람들`, `따뜻한 픽셀아트`라는 분위기와 화면 구성을 참고한다.

실제 제작물은 캐릭터, 얼굴 비율, 건물, 푸드트럭, 팔레트, 달리기 프레임을 새로 설계한다. 첨부 이미지를 그대로 자르거나 트레이싱하지 않는다.

### 화면의 움직임

러너는 화면 하단 중앙 부근에서 제자리 달리기를 한다. 배경이 오른쪽에서 왼쪽으로 흐르면서 앞으로 달리는 느낌을 만든다.

| 레이어 | 움직임 | 상대 속도 |
|---|---|---:|
| 하늘과 계절 그라데이션 | 거의 정지 | 0× |
| 구름과 먼 새 | 아주 느리게 이동 | 0.05× |
| 남산·도시 실루엣 | 느리게 이동 | 0.12× |
| 한강·다리·먼 건물 | 완만하게 이동 | 0.25× |
| 나무·가로등·빌딩 | 중간 속도 | 0.5× |
| 도로와 난간 | 기준 속도 | 1× |
| 차선·콘·전경 풀 | 가장 빠르게 이동 | 1.4× |
| 러너 | 위치 고정, 6~8프레임 반복 | 8~12fps |

카메라 흔들림이나 빠른 줌은 사용하지 않는다. 발과 상체가 1~2픽셀 움직이고, 도로의 선이 흘러가는 정도로 충분히 달리는 느낌을 만든다.

### 대표 러너

메인 장면에는 순위를 암시하지 않는 1명의 상징 러너 또는 같은 선상에서 달리는 3명의 익명 러너를 사용한다.

20명의 실제 참가자 캐릭터를 트랙 위 앞뒤로 배치하지 않는다. 앞선 사람과 뒤처진 사람이 생기면 장면 자체가 경주처럼 보이기 때문이다. 참가자별 인증 상태는 아래의 고정 캐릭터 그리드에서 표현한다.

### 상품 배너와 장면의 결합

이전 기획의 큰 상품 배너를 장면 속 대형 빌보드로 넣는다.

- 빌보드는 움직이는 배경과 분리된 고정 HTML 영역이다.
- 빌보드 상단에 `오늘의 크루 · 신민희`처럼 관리자 등록 풀네임을 표시한다.
- 실제 상품 사진은 픽셀화하지 않고 선명한 원본 비율로 보여준다.
- 픽셀아트 프레임만 장면의 스타일과 맞춘다.
- 전체 영역이 움직이는 링크가 되지 않도록 CTA 버튼을 고정한다.
- 스크린리더에는 일반 상품 배너 제목과 설명으로 읽힌다.

데스크톱:

- 장면 안 빌보드가 대표 이미지와 제목을 함께 보여준다.
- 첫 화면 가로폭의 최소 40%, 장면 높이의 최소 55%를 차지해 배경 소품이 아니라 주 콘텐츠로 읽히게 한다.

모바일:

- 장면에는 작은 빌보드 표지만 남긴다.
- 실제 상품 이미지와 설명은 장면 바로 아래의 정적인 큰 카드로 분리한다.

이 구조면 러닝 애니메이션과 참가자 상품 메인 배너가 서로 자리를 빼앗지 않는다.

## 7. 애니메이션 구현 방식

### 첫 구현 권장안

**정적 배경 이미지 + CSS 패럴랙스 레이어 + CSS 스프라이트 + 일반 HTML UI**를 사용한다.

- 정해진 경로와 단순 반복 움직임에는 Canvas가 필요하지 않다.
- 배경은 반복 가능한 긴 WebP 이미지로 만든다.
- 러너는 6~8프레임 스프라이트 시트와 CSS `steps()`를 사용한다.
- 위치 이동은 레이아웃 속성 대신 `transform`으로 처리한다.
- 픽셀 그래픽에는 `image-rendering: pixelated`를 적용한다.
- 인증률, 이름, 버튼, 상품 설명은 애니메이션 이미지가 아니라 일반 HTML로 제공한다.

Canvas는 등장 개체가 크게 늘거나 자유 이동이 필요할 때만 후속 검토한다. WebGL과 게임 엔진은 현재 범위에 사용하지 않는다.

### 성능 예산

- 모바일 메인 배경: 최적화 후 약 200~250KB 목표
- 데스크톱 메인 배경: 약 350~450KB 목표
- 현재 러너 스프라이트 세트: 100KB 안팎 목표
- 상품 대표 이미지까지 포함한 초기 신규 이미지 전송량: 800KB 이하 목표
- 러너 스프라이트 프레임 전환: 8~12fps
- CSS 패럴랙스 이동은 화면 주사율에 맞춰 합성되므로 큰 래스터 레이어 수를 제한
- 데스크톱은 최대 5개, 모바일은 처음부터 2~3개의 움직이는 레이어만 사용
- 디코딩된 이미지 메모리 예산: 모바일 24MB 이하, 데스크톱 48MB 이하 목표
- 레이아웃 시프트를 막기 위해 모든 이미지 비율을 미리 지정
- 현재 챕터의 장면만 우선 로드
- `Save-Data`가 꺼져 있고 네트워크가 충분할 때만 다음 챕터 장면을 유휴 시간에 미리 받기
- `IntersectionObserver`로 화면 밖에서는 실제 애니메이션 중지
- `visibilitychange`로 다른 탭에서는 실제 애니메이션 중지
- 관리자 게시 때만 데이터 갱신하고 상시 웹소켓을 사용하지 않음
- 상품 이미지는 업로드 때 모바일·데스크톱 파생본 생성, 재인코딩, EXIF 제거
- 외부 상품 링크는 `https`만 허용하고 이미지 사용권과 광고·협찬 여부 기록

### 모션 접근성

- `애니메이션 멈춤` 버튼을 움직이는 레이어와 분리된 접근 가능한 HTML UI에 제공한다.
- 선택 상태는 브라우저에 기억한다.
- `prefers-reduced-motion: reduce`에서는 배경 이동과 러닝 동작을 모두 끈다.
- 정지 상태에서도 오늘의 상품, 공통 목표, 인증률, 참가자 상태를 모두 이용할 수 있어야 한다.
- 빠른 점멸, 폭죽, 화면 흔들림, 강한 패럴랙스를 사용하지 않는다.
- 색만으로 인증 완료를 구분하지 않고 `오늘 달렸어요` 텍스트와 체크를 함께 쓴다.
- 스크린리더에 프레임 변화를 계속 알리지 않는다.

## 8. 오늘의 공통 문구

요청한 문구를 기본값으로 사용한다.

> **오늘 아침, 20명 중 14명이 달렸어요.**

표현 원칙:

- 활성 참가자 수와 완료 인원으로 숫자를 자동 생성한다.
- `6명 남았어요`, `70%만 달성했어요`를 이어 붙이지 않는다.
- 완료 순서나 마지막 완료자를 알리지 않는다.
- 운영자가 아직 반영 중이면 마지막 반영 시각을 함께 표시한다.

오전 8시 전에는 압박을 줄이기 위해 다음 문장을 사용할 수 있다.

> 오늘 아침, 달리기 기록이 모이고 있어요.

오전 8시 이후 또는 운영자 집계가 게시된 뒤에는 요청한 문구를 표시한다.

## 9. 공통 목표

공통 목표는 퍼센트 숫자를 높이는 것이 아니라 100개의 아침을 함께 남기는 것이다.

### 시즌 공통 목표

> **100일 동안 100개의 아침 풍경을 남깁니다.**

### 매일의 행동 목표

> **오전 8시 전, 각자의 속도로 3km.**

공통 목표로 사용하지 않는 것:

- 평균 인증률 80% 달성
- 전원 100일 인증
- 지난달 기록 경신
- 하루 전원 미완료 시 초기화
- 누적 거리 목표

## 10. 일간·주간·월간·100일 인증률

### 화면에 보여주는 네 항목

```text
오늘 인증률       70%
이번 주 인증률    68%
9월 인증률        72%
100일 누적 인증률 69%
```

네 수치는 크기와 색을 동일하게 사용한다.

- 순위 없음
- 목표선 없음
- 전 기간 대비 상승·하락 화살표 없음
- 녹색·빨간색 구간 없음
- 최고·최저 표시 없음
- 소수점 없이 반올림한 정수
- 공통 카드에는 퍼센트만 표시
- 분모·분자와 계산식은 도움말에서만 설명

### 계산의 기본 단위

한 참가자가 하루에 조건을 여러 번 충족해도 분자는 최대 1이다.

```text
E(d) = 날짜 d의 시작 시점에 시즌 참여 대상인 참가자 집합
D(d) = E(d)의 인원수
C(p,d) = 참가자 p가 날짜 d에 오전 인증을 완료하면 1, 아니면 0
N(d) = 날짜 d의 C(p,d) 합계
```

오전 인증 완료 판정은 다음처럼 고정한다.

```text
Q(p,d)
= 날짜 d의 관리자 승인 기록 중 before_8_verified = true인 거리의 합계

C(p,d)
= Q(p,d) >= 3,000m 이면 1, 아니면 0
```

- 기본 기준은 실제 활동 종료 시각이 한국시간 오전 07:59:59 이하인 기록이다.
- 정확한 종료 시각이 없지만 증빙에서 오전 8시 전 완료가 확인되면 운영자가 `before_8_verified`를 명시한다.
- 업로드 시각과 관리자 입력 시각은 오전 인증 판정에 사용하지 않는다.
- 여러 기록을 합산할 때 `before_8_verified`인 기록의 거리만 합산한다.
- 오전 8시를 걸쳐 끝난 기록은 8시 전 구간 거리가 별도로 검증되지 않으면 오전 인증 거리에 포함하지 않는다.
- 기록 상태가 관리자 승인 상태가 아니면 분자에 포함하지 않는다.

### 일간 인증률

```text
N(오늘) ÷ D(오늘) × 100
```

예시:

```text
14명 ÷ 20명 = 70%
```

### 주간 인증률

현재 주에서 운영자가 집계를 끝낸 날짜만 포함한다.

```text
Σ N(d) ÷ Σ D(d) × 100
```

월요일부터 현재까지의 닫힌 날짜를 사용한다. 미래 요일과 아직 열려 있는 오늘을 미리 분모에 넣지 않는다.

### 월간 인증률

현재 달과 시즌이 겹치는 기간 중 집계가 끝난 날짜만 포함한다.

- 9월은 9월 23일부터 계산한다.
- 10월과 11월은 해당 월의 시즌 날짜를 계산한다.
- 12월은 12월 31일까지 계산한다.
- 미래 날짜를 분모에 넣지 않는다.

### 100일 누적 인증률

시즌 시작일부터 마지막으로 집계를 끝낸 날짜까지 계산한다.

```text
시즌 누적 Σ N(d) ÷ 시즌 누적 Σ D(d) × 100
```

일별 퍼센트의 단순 평균은 사용하지 않는다. 날짜별 참가자 수가 달라질 수 있기 때문이다.

### 집계 상태

관리자 화면에 날짜 상태를 둔다.

```text
open → reviewing → closed
```

- `open`: 인증을 모으는 중
- `reviewing`: 운영자가 OCR·직접 입력 결과를 확인하는 중
- `closed`: 해당 날짜의 모든 참가자 상태를 확인하고 일간 인증률 스냅숏 확정

공개 화면:

- 오늘이 `open` 또는 `reviewing`이면 일간 인증률을 `집계 중`으로 표시한다.
- 주·월·100일 인증률은 `closed` 날짜만 계산한다.
- 운영자가 사후 기록을 수정하면 해당 날짜와 상위 기간의 비율을 다시 계산한다.
- 모든 비율 옆에 마지막 반영 시각을 표시한다.

부분 등록 중에도 확인된 참가자 카드의 `오늘 달렸어요` 상태는 반영할 수 있다. 다만 오류 행이나 미확인 참가자가 남아 있으면 날짜를 `closed`로 바꾸거나 퍼센트를 확정하지 않는다.

날짜를 닫는 조건:

- 날짜 시작 시점의 대상자 스냅숏에 있는 모든 참가자가 `완료`, `기록 없음`, `운영 제외` 중 하나로 확인됨
- 오류 OCR 행이 남아 있지 않음
- 운영자가 최종 차이 미리보기를 확인함
- 분자와 분모 스냅숏을 하나의 트랜잭션으로 게시함

`closed` 이후의 사후 수정은 기존 스냅숏을 덮어쓰지 않고 새 정정 버전과 배치 ID를 남긴다.

### 참가자 수 변경

- 날짜 시작 시점의 실제 참여 대상자를 00:00 KST에 불변 스냅숏으로 저장하고 그날 분모로 사용한다.
- 신규 참여와 중단은 운영자가 지정한 효력일부터 반영한다.
- 결과를 본 뒤 과거 분모에서 특정 사람을 빼지 않는다.
- 과거 기록을 소급 수정하면 변경 이력을 보존한다.

## 11. 참가자 캐릭터 그리드

### 카드에 보이는 정보

- 관리자 등록 풀네임
- 캐릭터
- `오늘 달렸어요` 또는 `아직 기록 없음`
- 인증 완료 체크

### 배치 원칙

- 모든 참가자를 고정된 관리자 순서로 배치한다.
- 인증 완료 순서로 재정렬하지 않는다.
- 완료자는 따뜻한 아침빛과 작은 체크를 표시한다.
- 아직 기록이 없는 캐릭터는 평온한 기본 동작을 유지한다.
- 회색 처리, 빨간색, X, 낙오 문구를 사용하지 않는다.

풀네임은 관리자 참가자 등록 화면에서만 생성·수정한다. 참가자 로그인과 직접 수정 기능은 없다. 풀네임과 인증 상태의 공개 동의는 새 시즌 참여 조건으로 확정한다.

## 12. 캐릭터 클릭 개인 창

공통 화면에서 숨긴 개인 수치는 캐릭터를 눌렀을 때만 지연 조회한다.

```text
신민희

오늘 오전 인증 완료
3.24km · 운동시간 31분

[날짜 선택]
10월 8일 · 3.42km · 운동시간 34분

[신민희님의 상품·서비스 보기]
```

공개 항목:

- 풀네임
- 선택한 날짜의 인증 여부
- 선택한 날짜의 오전 유효 거리
- 운동 소요시간
- 완료일만 표시한 달력
- 상품·서비스 카드

공개하지 않는 항목:

- 정확한 출발·종료 시각
- GPS와 코스
- 인증 원본 이미지
- 앱명
- 업로드 시각
- 운영자 메모
- 개인 인증률
- 스트릭
- 누적 미완료 횟수

참가자 로그인이 없으므로 개인 창도 인터넷 공개 화면이다. 운영자는 시즌 참여 전에 풀네임과 러닝 기록의 공개 동의를 등록한다. 동의가 철회되면 대체 이름으로 계속 노출하지 않고 해당 참가자의 카드·기록·상품을 공개 화면에서 내린다.

### 개인 창 접근성

- 네이티브 `<dialog>` 또는 동등한 대화상자 역할과 제목을 사용한다.
- 열릴 때 제목 또는 첫 조작 요소로 포커스를 이동한다.
- 닫을 때 원래 선택한 참가자 카드로 포커스를 되돌린다.
- ESC와 명시적인 닫기 버튼을 모두 지원한다.
- 날짜 선택은 키보드만으로도 조작할 수 있게 한다.
- 움직이는 픽셀아트 레이어는 `aria-hidden`으로 두고 기록 정보는 별도의 고정 HTML 영역에 제공한다.

## 13. 2027로 가는 장면 변화

장면은 인증률이 아니라 날짜에 따라 자동 전환된다. 인증률이 낮아도 다음 계절이 잠기거나 러너가 멈추지 않는다.

### 1장 · 9월 23일~10월 12일

**첫 문을 여는 20일**

- 살구빛 하늘과 아직 푸른 강변
- 현관 앞 신발, 출발선 표지
- 상품 빌보드는 밝은 종이 포스터 형태

문구:

> 첫 아침은 속도보다 다시 나오기 쉬운 길을 만듭니다.

### 2장 · 10월 13일~11월 1일

**같은 시간의 길**

- 단풍색 나무와 길어진 그림자
- 한강 자전거길과 따뜻한 가로등
- 빌보드 프레임에 주황과 갈색 포인트

문구:

> 서로 다른 속도로 같은 아침을 반복합니다.

### 3장 · 11월 2일~11월 21일

**밝은 날과 흐린 날**

- 회청색 강과 옅은 안개
- 러너의 입김과 얇은 겉옷
- 맑음·구름·안개가 번갈아 등장

문구:

> 다른 날씨와 다른 컨디션도 모두 100일의 일부입니다.

### 4장 · 11월 22일~12월 11일

**겨울로 이어지는 길**

- 겨울 남색, 따뜻한 창문, 첫서리
- 다리와 도시의 조명이 조금씩 늘어남
- 빌보드는 따뜻한 라이트박스 형태

문구:

> 비어 있던 다음 칸에 다시 불이 켜지는 것도 루틴입니다.

### 5장 · 12월 12일~12월 31일

**2027의 문 앞**

- 겨울 새벽과 절제된 금색 조명
- 멀리 보이는 `2027` 도로 표지
- 하루가 지날수록 표지와 새해 하늘이 조금 더 가까워짐
- 12월 31일에는 강 건너 전광판에 `NEXT MORNING · 2027`

문구:

> 모은 아침을 들고 새로운 해로 갑니다.

### 시즌 마지막

12월 31일의 집계가 끝나면 폭죽이나 전원 성공 연출 대신 다음 문장을 보여준다.

```text
2027로 가는 100번의 아침이 완성되었습니다.

서로 다른 밝기의 100개 아침이
같은 길 위에 남았습니다.

다음 아침은 2027입니다.
```

## 14. 경쟁 없이 퍼센트를 보여주는 방식

인증률은 점수가 아니라 `기록된 아침 자리의 비율`로 설명한다.

### 사용 원칙

- 네 퍼센트에 동일한 색과 크기를 사용한다.
- 특정 인증률에 따라 등급이나 칭호를 주지 않는다.
- 높은 날은 성공, 낮은 날은 실패라고 부르지 않는다.
- 지난주·지난달 대비 증감 화살표를 사용하지 않는다.
- 개인 인증률을 공통 화면에 표시하지 않는다.
- 다음 배경이나 상품 배너를 인증률로 해금하지 않는다.
- 러너의 속도를 인증률과 연결하지 않는다.

### 풍경과 인증률의 분리

- 날씨, 밝기, 계절, 러너 속도는 날짜와 시간대에 의해서만 바뀐다.
- 인증률이 낮다고 안개가 짙어지거나 장면이 어두워지지 않는다.
- 인증률이 높다고 러너가 빨라지거나 추가 오브젝트가 해금되지 않는다.
- 인증 완료는 해당 참가자 카드의 빛과 체크에만 반영한다.

인증률 숫자는 풍경과 분리된 일반 HTML 텍스트로 제공한다. 이렇게 해야 배경이 공동 성적표가 되지 않는다.

## 15. 관리자 운영 변경

### 참가자 등록

관리자가 다음을 등록한다.

- 풀네임
- 캐릭터
- 표시 순서
- 시즌 참여 시작일과 종료일
- 상품·서비스 정보
- 공개 동의 상태와 동의 버전

풀네임 공개 동의가 확인된 참가자만 새 시즌의 공개 참가자로 등록한다. 동의 확인이 없으면 공개 시즌에 등록하지 않고, 철회되면 해당 참가자의 공개 카드와 기록을 즉시 내린다.

### 인증 일괄 등록

기존 최대 20장 OCR과 검토 표를 재사용한다.

1. 날짜 선택
2. 이미지 일괄 업로드 또는 표 붙여넣기
3. 참가자·거리·운동시간 제안
4. 오전 인증 여부 확인
5. 정상·오류 행 미리보기
6. 정상 행 게시, 오류 행 초안 보류, 날짜는 `reviewing` 유지
7. 대상자 전원의 `완료 / 기록 없음 / 운영 제외` 상태 확인
8. 최종 날짜 스냅숏을 트랜잭션으로 게시하고 `closed`로 변경
9. 공동 인증률 재계산과 공개 캐시 갱신

과거 기록을 수정하면 실제 활동 날짜의 비율을 다시 계산하고 배치 ID와 변경 이력을 남긴다.

### 상품 배너

- 20명에게 100일 동안 5회씩 동일 노출
- 풀네임과 상품명은 관리자 승인 데이터만 사용
- 100일을 20일 순환 5회로 나누고, 각 순환에 모든 참가자가 정확히 한 번 등장
- 배너는 해당 날짜 24시간 동안 같은 크기로 노출
- 주말 노출 횟수 차이는 최대 1회
- 인증 여부·거리·클릭 수에 따라 순서 변경 금지
- 공개 조회수와 인기 순위 없음
- 장면 속 빌보드와 모바일 정적 카드가 같은 데이터를 사용

## 16. 개인정보와 공개 범위

풀네임과 매일의 인증 상태를 인터넷에 함께 공개하므로 명시적인 공개 동의가 필요하다.

운영자가 보관할 항목:

- 공개 항목
- 공개 도메인
- 시즌 공개 기간
- 철회 방법
- 동의 버전과 일자

공개 API는 관리자 기록 전체를 반환하지 않고 다음 허용 필드만 제공한다.

```text
display_name
character_id
today_completed
selected_record_date
selected_record_distance
selected_record_duration
public_product_summary
```

공개 동의가 유효한 참가자의 `display_name`에는 관리자 등록 풀네임이 들어간다. 이 필드명을 사용하면 동의 철회 시 내부 원본 이름을 공개 응답과 분리하기 쉽다.

정확한 생활 시각, GPS, 인증 이미지, 앱명, 업로드 시각, 미완료 사유는 공개하지 않는다.

풀네임이 공통 그리드에 나오므로 참가자 상세뿐 아니라 새 시즌 공개 대시보드 전체를 기본 `noindex`로 설정한다. 이는 접근 통제가 아니며 공개 동의를 대신하지 않는다.

- 동의 철회 시 카드와 상세 HTML, 공개 JSON, 이미지 파생본, CDN 캐시를 함께 무효화한다.
- 시즌 종료 후 정한 공개 종료일에 개인 러닝 기록을 자동 비공개로 전환한다.
- 이전 시즌처럼 운영자는 동결 기록을 관리자 화면에서 계속 열람할 수 있다.
- 상품 이야기 아카이브를 계속 공개할지는 러닝 기록 공개 기간과 별도로 정한다.

### 관리자 계정과 복구

- 관리자 계정은 MFA와 오프라인 복구 코드를 사용한다.
- 배치 게시, 날짜 마감, 사후 정정, 동의 철회, 배너 변경 전에 필요한 경우 재인증한다.
- 모든 게시 전 기존값과 새 값의 차이를 미리 보여준다.
- 게시·수정·되돌리기·동의 철회·배너 변경을 배치 ID와 서버 시각으로 기록한다.
- 배치 단위 되돌리기를 제공하되 원본 이력은 물리 삭제하지 않는다.
- 인증 원본 이미지는 관리자에게만 보관하고 정한 보유기간 뒤 자동 파기한다.
- 픽셀아트 원본, 작가·외주 계약, 라이선스, 상품 이미지 사용권 이력을 보관한다.

## 17. 기존 코드 재사용

현재 로컬 코드에서 유지할 수 있는 기반:

- 기존 대시보드 헤더와 레이아웃
- `DashboardClient` 상단 슬롯
- 멤버 상품 배너 POC
- 참가자 캐릭터 그리드와 클릭 팝업
- 최대 20장 관리자 OCR
- 공개 대시보드 갱신 구조

새로 필요한 것:

- 픽셀아트 장면과 5개 날짜 챕터 설정
- 정적 POC 배너를 장면 속 데이터 기반 빌보드로 변경
- 풀네임 공개 필드와 동의 상태
- 일·주·월·100일 인증률 계산
- 날짜별 집계 상태 `open / reviewing / closed`
- 모션 정지와 저감 옵션
- 관리자 게시 후 비율 캐시 갱신

## 18. 첫 구현 범위

### 첫 구현에 포함

- 한 개의 가을 픽셀아트 배경
- 같은 장면의 데스크톱·모바일 파생 아트와 모바일 2~3 레이어 구성
- 5개 기간의 색상 팔레트와 계절 오버레이 설정
- 도로 흐름과 대표 러너 스프라이트
- 장면 속 상품 빌보드
- 요청한 공통 문구
- 공통 목표
- 네 가지 인증률과 집계 상태
- 풀네임 참가자 카드와 완료 상태
- 선택 날짜 거리·운동시간 개인 창
- 애니메이션 멈춤과 reduced-motion
- 관리자 일괄 등록 연동
- 12월 31일 `NEXT MORNING · 2027` 최종 상태

### 검증 후 추가

- 2~5장 겨울·연말 전용 배경 원화
- 구름, 새, 지하철, 강물 반짝임
- 실제 2027 첫빛을 보여주는 1월 1일 시즌 아카이브 화면

## 19. 검증 기준

### 기능

- 관리자가 등록한 풀네임과 상태가 정확히 보이는가
- 네 인증률의 분모와 분자가 날짜별 대상자 기준으로 맞는가
- 미래 날짜와 열린 날짜가 기간 비율에 들어가지 않는가
- 캐릭터 클릭 전 개인 기록이 초기 응답에 포함되지 않는가
- 사후 수정 시 과거와 누적 비율이 함께 갱신되는가

### 경험

- 퍼센트가 순위표처럼 느껴지지 않는가
- 아직 기록이 없는 참가자가 실패자로 보이지 않는가
- 2027로 가는 변화가 날짜 흐름으로 읽히는가
- 상품 배너가 러닝 장면 안에서도 충분히 읽히는가
- 움직임이 게임 레이스처럼 보이지 않는가

### 성능과 접근성

- 저사양 안드로이드에서 끊김이 심하지 않은가
- 애니메이션을 멈춰도 모든 정보가 남는가
- 키보드로 참가자 카드와 상품 링크를 사용할 수 있는가
- 화면 밖과 백그라운드에서 애니메이션이 멈추는가
- 움직임 저감 설정에서 완전히 정지된 화면을 제공하는가

## 20. 안전한 로컬 전환 순서

1. 이전 시즌 동결 상태 확인
2. 새 시즌 풀네임·공개 동의 필드 설계
3. 인증률 공식과 집계 상태부터 구현·테스트
4. 참가자 카드와 개인 창 정보 경계 적용
5. 한 장면의 픽셀아트 POC 연결
6. 상품 배너를 장면 속 빌보드로 연결
7. 관리자 일괄 등록과 공개 캐시 갱신 연결
8. 모바일·저감 모션·키보드 접근성 검증
9. 계절 장면을 순차적으로 추가

모든 단계는 로컬에서만 진행하며, 별도 승인 전에는 푸시·배포·프로덕션 데이터 변경을 하지 않는다.

## 21. 최종 추천

이 기획의 핵심은 **사람이 아니라 날짜가 앞으로 달리는 것**이다.

- 참가자는 서로 앞지르지 않는다.
- 풀네임과 오늘의 인증 상태는 같은 자리에서 편안하게 보인다.
- 상세 거리와 운동시간은 캐릭터 안쪽에만 있다.
- 퍼센트는 목표 달성 점수가 아니라 함께 남긴 아침의 기록이다.
- 상품 배너는 장면 속 오늘의 빌보드가 된다.
- 풍경은 인증률과 무관하게 가을에서 겨울로, 2026년에서 2027년으로 이동한다.

이를 통해 첨부 이미지처럼 실제로 달리는 감각을 주면서도, 대시보드는 경주가 아니라 모두가 같은 시간 속을 지나가는 공동 기록장으로 남는다.
