## 변경

- 배너 하단 페이지 점/넘김 영역 및 관련 CSS 제거. 화살표를 남은 이미지 영역의 중앙(50%)에 정렬. 좌우 이동·스와이프·7초 전환·일시정지 유지.
- 대시보드 날씨 안내 푸터 제거. 예보 기반 연출은 유지하며 출처·CC BY 4.0 링크·단순화 설명은 `/terms#weather-data`로 이동. [MET Norway 출처 안내](https://api.met.no/doc/License)를 확인했다.
- 내 활동 첫 화면은 사진·이름과 `프로필 / 인증샷 / 활동` 3열 메뉴만 표시한다. 상태 설명·메뉴 부연·하단 보조 메뉴 제거. 상세에서도 세 메뉴로 바로 이동한다. 기존 대시보드 개인 기능 진입점은 유지.
- 각 기능의 동적 로딩을 별도로 처리해 내용을 불러오는 중에도 세 메뉴가 사라지지 않는다. 프로필/인증샷 입력 유지와 계정별 상태 격리는 유지.
- 공개 댓글의 읽기 전용 `onManage` 설정과 중복 관리 버튼 제거. 본인 글/댓글/답글은 해당 위치에서 수정·삭제하며, 다른 사람의 글에는 편집 버튼이 없다. 댓글 작성·답글·반응도 해당 영역에서 이용한다. 공개 멤버 프로필은 계속 읽기 전용.
- 빈 상태 메시지에도 `min-height`를 적용하던 것이 불필요한 여백의 원인이었다. 빈 상태 노드를 렌더링하지 않고 높이 예약도 없앴다. 실제 오류/처리 안내는 필요할 때만 표시한다.
- 댓글 PATCH는 카카오 계정을 서버 검증하고 ID·4기·소유자 actor key·visible 상태·기존 updated_at을 모두 일치시켜 원자적으로 갱신한다. 사용자 입력의 소유자·승인 상태는 신뢰하지 않는다. 익명 표시 댓글도 소유 키로 판단한다.
- 작성 시각 유지, `updated_at > created_at`일 때 한국 시간으로 수정 시각을 추가 표시. 기존 updated_at 열을 사용하므로 스키마 변경/백필 없음. 이 열은 운영자의 상태 변경 시에도 갱신된다.
- 수정 결과는 본문·수정 시각만 병합해 답글/반응을 보존한다. 저장보다 먼저 시작된 GET이 내용을 되돌리지 않도록 응답 순서 검사. 생성·수정·삭제 성공 뒤 캐시 무효화 및 응답 이후 서버 Realtime 갱신 알림.

## 검증

- 전체 103개 테스트, 수정 파일 ESLint, 운영 TypeScript·Next 빌드 통과.
- 실제 PATCH 함수 본문을 격리된 포트로 실행: 비로그인·CSRF·빈 본문 거절, 소유자/시즌/상태/수정시각 조건, 타인 글·오래된 폼 409, 수정 시각 응답, 캐시 갱신 확인.
- 390px 로컬 미리보기: 세 메뉴 한 줄, 모바일 하단 시트, 콘텐츠 로딩 중 메뉴 유지, 인증샷→활동→프로필 이동 확인. 실제 회원 데이터 변경 없음.
- 최종 운영 로그인 화면: 이름→세 메뉴 표시, 페이지 점/날씨 푸터/빈 status 모두 0개. 본인 답글의 수정·삭제 버튼 확인, 수정창의 150자 제한과 취소, 삭제 확인창과 취소 확인. 원문 `^^` 유지, 612px 가로 넘침 및 콘솔 오류 없음.
- 운영 GET 조회: 대시보드·이용약관·댓글 200, 댓글 live 및 updatedAt 제공 확인. 운영 데이터에 시험 PATCH를 보내는 요청은 안전 검사에서 차단돼 실행하지 않았다. 실사용 댓글을 저장/삭제하는 전체 쓰기 검증은 수행하지 않았으며, 기존 게시물은 변경/삭제하지 않았다.
