# 4기 보관함

내 정보는 나의 활동 / 도구 / 보관함 순서로 표시한다. 보관함은 `daily_gift_claims`의 `🎁 ` 상품 당첨 내역과 운영자 직접 지급을 함께 표시한다. 기존 당첨은 원래 문구와 받은 날짜를 유지하며, 추첨 설정 변경으로 다시 추첨하거나 이름을 덮어쓰지 않는다.

멤버는 본인의 사용 가능한 항목에 요청 내용을 남길 수 있다. 운영자는 어드민 > 보관함에서 멤버를 선택해 지급하거나 요청을 완료/반려한다. 반려하면 다시 사용 가능하며 이전 요청과 사유는 남는다. 완료 버튼은 혜택 제공 또는 기록 반영을 운영자가 마친 후 누른다. 운동 기록 자체를 자동 수정하지 않는다.

## 저장과 권한

- 멤버 API: `/api/me/locker`. 서버가 승인된 계정 연결에서 소유자와 멤버를 결정한다.
- 운영자 API: `/api/admin/hello-2027/locker?participant=UUID`. 기존 OTP 운영자 세션과 멤버 소유권/시즌을 확인한다.
- 비공개 `member-run-uploads` 버킷의 `locker/4th/{local|live}/{owner}/{participant}`에 변경 이력을 저장한다. 로컬과 운영 이력은 분리한다.
- 변경은 서버가 부여한 처리자, 시각, 상태, 사유와 요청 ID를 저장한다. 멤버 입력으로 처리자나 권한을 지정하지 않는다.
- 덮어쓰기 없는 임시 업로드만으로는 동시성 보호가 안 된다. 실제 저장소에서 동시 업로드가 둘 다 성공하는 것을 확인했다. 고유 임시 파일을 만들고 **move**로 다음 순번의 파일 경로를 예약한다. 목적지가 존재하면 충돌로 반환하고 새로고침을 요구한다. 저장 완료된 순번 파일은 수정/삭제하지 않는다.
- 요청 ID가 이미 기록됐으면 다시 지급/사용 처리하지 않고 현재 보관함을 반환한다. 재시도 시 같은 요청 ID를 유지한다.
- 응답은 private/no-store이며 공개 대시보드 데이터에 포함하지 않는다.

## 검증

`tests/member-locker.test.mjs`: 상태 전이, 재요청, 역할 제한, 중복/동시 처리, 재시도, 저장 오류.
`scripts/check-locker-storage.mjs`: 실제 비공개 저장소의 격리된 임시 경로에서 동시 move와 읽기 확인 후 테스트 파일 제거. `.env.local`이 필요하며 기존 멤버 기록을 변경하지 않는다.
