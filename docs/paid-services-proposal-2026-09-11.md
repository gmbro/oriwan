# TWTT 교정운동·광고 유료화 제안

2026-09-11 기준. 아래 가격은 초기 판매 실험을 위한 제안이며, 교정운동 시장 평균이나 확정 요금이 아니다. 결제 기능은 이번 변경에 포함하지 않았다.

## 시작 상품

| 상품 | 제안 판매가 | 포함 범위 |
| --- | ---: | --- |
| 온라인 교정운동 피드백 | 1회 39,000원 | 영상 1개 검토, 운동 가이드 3개, 7일 안에 후속 피드백 1회 |
| 대면 교정운동 | 50분 79,000원 | 움직임 확인, 개인 운동 지도, 집에서 할 운동 정리 |
| 초기 파트너 배너 | 4주 30,000~50,000원 | 배너 1개, 링크 1개, 문구 수정 1회, 게시 기간 보고 |

온라인 상품은 검토와 피드백을 합쳐 운영자 작업 30~40분을 목표로 한다. 무제한 상담을 포함하면 수익이 급격히 줄어든다. 대면 가격은 장소 비용·이동 시간·지도자의 경력에 맞춰 조정한다. 소비자에게는 최종 결제 총액을 보여준다.

비교 자료로 숨고의 일반 PT 안내는 시간당 평균 50,000원을 제시한다. 이는 해당 플랫폼 견적 자료이며 전문 교정운동의 평균 가격은 아니다. TWTT 대면 제안은 개별 가이드까지 제공한다는 가정이다. [숨고 PT 비용](https://soomgo.com/prices/퍼스널트레이닝)

광고비는 실제 활성 이용자·노출·클릭 자료가 없는 상태에서 높게 책정하기 어렵다. 초기 파트너 가격으로 시작하고 4주마다 결과를 공유한다. 교체 배너 1개는 독점 노출이 아니므로 순환 게시임을 명시한다. 유료 광고는 ‘광고’ 또는 ‘스폰서’로 표시한다. 최소 노출량이나 문의 수는 측정 체계와 계약 조건이 준비되기 전에 보장하지 않는다. 활성 이용자와 성과가 확인되면 다음 계약부터 4주 100,000원 수준을 시험한다. 기존 계약 중간에 요금을 올리지 않는다.

## 앱에서 청구하는 순서

초기에는 정기 구독보다 상품별 단건 결제를 권한다.

- 교정운동: 기존 신청 → 운영자가 방식·일정·제공 범위 확인 → 앱의 내 신청에 ‘39,000원 결제하기’ 표시 → 결제 확인 → 일정 확정 → 서비스 완료.
- 광고: 광고 문의 → 소재·링크·기간 검토 → 금액과 노출 위치를 표시한 결제 요청 → 결제 확인 → 지정일 게시 → 종료일 자동 종료 → 결과 보고 및 별도 연장 결제.

결제 전 화면에는 총액, 제공 범위, 일정/게시 기간, 취소·환불 조건을 함께 표시한다. 운영자 화면에는 결제 요청, 결제 완료, 제공 중, 완료, 취소·환불 상태와 주문별 내역이 필요하다. 이용자가 결제하지 않은 요청은 확정 예약이나 유료 광고로 표시하지 않는다.

토스페이먼츠의 현재 주문서형/결제창형 결제위젯을 붙이면 카드·간편결제를 한 흐름으로 제공할 수 있다. 결제 성공 화면만 보고 서비스를 열지 않고, 서버에서 주문번호·금액·결제 결과를 검증한 뒤 상태를 바꾼다. 같은 주문의 중복 승인/중복 게시를 막고, 결제 조회와 웹훅으로 취소·입금 결과를 맞춘다. [공식 결제위젯 안내](https://docs.tosspayments.com/guides/v2/payment-widget), [결제 승인 안내](https://docs.tosspayments.com/guides/v2/payment-window/integration), [웹훅 안내](https://docs.tosspayments.com/reference/using-api/webhook-events)

## 결제 비용

토스페이먼츠 공시 일반 카드 수수료는 3.4%, 수수료의 부가세 10% 별도다. 일반 요율 적용 시 수수료 총액은 결제액의 3.74%이며, 39,000원 결제에서는 약 1,459원이다. 실제 계약·우대 수수료에 따라 달라진다. 가입비 220,000원과 연관리비 110,000원도 공시되어 있으나 계약 형태에 따라 다르므로 실제 견적을 확인해야 한다. [공식 이용요금](https://www.tosspayments.com/about/fee)

수요가 아직 적으면 PG 고정비를 포함한 손익을 먼저 계산하고, 초기 문의를 통해 유료 전환 의사를 확인한 뒤 결제를 구현한다. 앱 결제 연동의 다음 작업 범위는 상품/주문 데이터, 운영자 결제 요청, 사용자 결제 화면, 서버 승인, 취소·환불, 결제 결과 동기화까지다.
