# TWTT 4기 오늘의 응원 상자 기획

작성일: 2026-09-02  
참고 경험: [box.cyhuh.com](https://box.cyhuh.com/)의 단순한 상자 개봉 흐름 + 토스 만보기의 즉시 보상 감각

## 1. 제품 정의

매일 공식 인증이 완료된 크루가 본인 화면에서 선물상자 하나를 열고, 랜덤 응원 메시지 하나를 받는 기능이다.

초기 보상은 금전 가치가 없는 문구이므로 사용자-facing 명칭은 `랜덤 상품`보다 `오늘의 응원 상자`를 쓴다. 실제 쿠폰이나 물품을 넣는 시점에는 별도의 재고·당첨 고지·배송 정책을 추가한다.

## 2. 핵심 원칙

- 로그인하고 운영자 승인이 끝난 본인만 상자를 연다.
- 한국시간 기준 하루 인증 1건당 상자 1개만 지급한다.
- 클라이언트가 보낸 참가자 ID나 상품 ID를 신뢰하지 않는다.
- 같은 날 여러 번 누르거나 네트워크가 재시도돼도 최초 결과를 그대로 보여준다.
- 운영자가 문구나 확률을 나중에 바꿔도 이미 받은 결과는 바뀌지 않는다.
- 공개 크루 목록에서는 다른 사람의 상자를 열 수 없고, `오늘 선물 받음` 같은 상태만 선택적으로 보여준다.

## 3. 사용자 흐름

주 진입점은 `/4th` 메인 배너 바로 아래의 `응원 상자` 액션이며, 클릭하면 모바일 바텀시트·웹 중앙 팝업으로 연다. `/me`에서도 같은 상태를 다시 확인할 수 있다. `box.cyhuh.com`을 유지한다면 같은 Next 앱의 `/gift-box`를 해당 서브도메인으로 연결해 로그인 세션과 API를 공유한다.

| 상태 | 화면 문구 | 행동 |
| --- | --- | --- |
| 미로그인 | 로그인하면 오늘의 상자를 확인할 수 있어요 | 로그인 |
| 계정 연결 대기 | 크루 계정을 확인하고 있어요 | 승인 안내 |
| 오늘 미인증 | 오늘 인증을 완료하면 상자가 도착해요 | 인증하기 |
| 검수 중 | 인증을 확인하고 있어요 | 자동 갱신 |
| 개봉 가능 | 오늘의 응원 상자가 도착했어요 | `열어보기` |
| 개봉 중 | 상자 여는 중 | 중복 클릭 방지 |
| 개봉 완료 | 응원 문구 + `오늘 선물 받음` | 닫기/공유 |
| 과거 미개봉 | 지난 인증 상자 N개가 기다리고 있어요 | 날짜별 개봉 |
| 오류 | 상자를 다시 열어주세요 | 동일 요청 재시도 |

개봉 애니메이션은 0.6~0.9초의 짧은 흔들림과 뚜껑 열림으로 끝낸다. `prefers-reduced-motion` 환경에서는 애니메이션 없이 결과를 즉시 보여준다. 소리와 진동은 기본 비활성으로 두고 사용자가 직접 켠 경우에만 실행한다.

## 4. 초기 응원 문구

MVP는 아래 네 문구를 동일 가중치 25%로 시작한다.

| 코드 | 문구 | 톤 |
| --- | --- | --- |
| `envy` | 부럽네요! | celebrate |
| `great-job` | 참 잘했어요! | praise |
| `keep-going` | 오늘도 화이팅! | cheer |
| `thank-you` | 고생하셨어요 :) | thanks |

문구는 1~60자로 제한하며 욕설, 개인정보, 외부 링크, HTML은 저장하지 않는다. 운영 화면에서는 문구, 톤, 가중치, 게시 여부, 시작일, 종료일, 정렬 순서를 편집한다. 삭제 대신 비활성화해 과거 수령 기록을 보존한다.

## 5. 지급 규칙

1. 서버가 승인된 로그인 계정과 현재 활성 4기 참가자를 확인한다.
2. 서버 기준 한국 날짜의 `daily_certifications.completed = true`를 확인한다.
3. 인증이 개봉 가능 상태면 활성 응원 문구 중 하나를 서버에서 추첨한다.
4. 추첨 결과와 당시 문구를 한 트랜잭션으로 저장한다.
5. 같은 시즌·참가자·인증일의 중복 요청은 새로 추첨하지 않고 저장된 결과를 반환한다.

권장 운영 정책은 다음과 같다.

- OCR 지연이나 운영자 소급 승인으로 상자를 잃지 않도록 시즌 종료 후 7일까지 과거 미개봉 상자를 열 수 있다.
- 리커버리 인증의 지급 여부는 시즌 설정의 `reward_eligible` 정책으로 명시한다.
- 인증이 나중에 취소되어도 이미 연 결과를 재추첨하거나 삭제하지 않고 취소 사유만 감사 로그에 남긴다.
- 실제 물품·쿠폰이 추가되기 전까지 무한 재고인 응원 문구만 운영한다.

## 6. 데이터 구조

### `gift_box_prizes`

- `id`
- `season_id`
- `code`
- `message`
- `tone`: `cheer | praise | thanks | celebrate`
- `weight`: 양의 정수
- `active`
- `starts_on`, `ends_on`
- `display_order`
- `created_by`, `updated_by`, `created_at`, `updated_at`
- 고유키: `(season_id, code)`

### `daily_gift_claims`

- `id`
- `season_id`
- `season_participant_id`
- `certification_date`
- `daily_certification_id`
- `prize_id`
- `prize_message_snapshot`
- `prize_tone_snapshot`
- `algorithm_version`
- `opened_at`, `created_at`
- `eligibility_revoked_at`, `eligibility_revoked_reason`
- 고유키: `(season_id, season_participant_id, certification_date)`

문구 스냅샷을 저장해야 운영자가 원본 문구를 수정해도 이미 받은 결과가 바뀌지 않는다.

## 7. API 경계

- `GET /api/me/gift-boxes`
  - 오늘과 과거 미개봉 상자의 `locked | reviewing | available | opened | expired` 상태를 반환한다.
- `POST /api/me/gift-boxes/[certificationDate]/claim`
  - 요청 본문에서 참가자·상품 ID를 받지 않는다.
  - 최초 개봉이면 `newlyOpened: true`, 중복 요청이면 저장된 결과와 `newlyOpened: false`를 반환한다.
- `GET /api/admin/gift-prizes`
  - 시즌별 문구와 개봉 통계를 조회한다.
- `POST/PATCH /api/admin/gift-prizes`
  - 기존 관리자 인증을 재사용하고 문구·가중치·기간을 서버에서 다시 검증한다.

추첨은 서버의 암호학적 난수와 누적 가중치를 사용한다. 실제 지급 보장은 프로세스 메모리나 `Math.random()`이 아니라 DB 고유 제약과 원자적 트랜잭션이 담당한다.

## 8. 운영 어드민

`/admin`에 `선물상자 관리`를 추가한다.

- 활성 시즌 선택
- 응원 문구 등록·수정·비활성화
- 톤 및 확률 가중치 설정
- 게시 시작·종료일 설정
- 모바일 개봉 화면 미리보기
- 날짜별 개봉 가능/완료/만료 수 조회
- 참가자별 지급 이력 조회
- 인증 취소 시 감사 사유 확인

가중치는 상대값으로 입력하되 화면에는 예상 확률을 자동 계산해 보여준다. 예를 들어 네 문구가 모두 `1`이면 각각 25%다.

## 9. 보안과 오류 처리

- 동일 출처 검사, CSRF 방어, 요청 크기 제한, 로그인·승인 참가자 확인을 모두 서버에서 수행한다.
- 개봉 API에는 짧은 사용자별 속도 제한을 적용하되, 핵심 중복 방지는 DB 고유키로 처리한다.
- 응원 문구는 일반 텍스트로만 렌더링하고 HTML을 허용하지 않는다.
- 관리자 변경은 생성자·수정자·시각과 함께 감사 로그에 남긴다.
- 여러 탭에서 동시에 개봉해도 하나의 결과만 저장되고 모든 탭이 같은 결과를 받는다.

## 10. 단계별 출시

### 1단계 — 메시지형 MVP

- 로그인 본인 인증
- 인증 완료 후 1일 1상자
- 네 개 기본 문구 동일 확률
- 개봉 결과 영구 저장
- 운영자 문구·가중치 관리

### 2단계 — 리텐션

- 과거 미개봉 상자 모아보기
- 연속 인증 배지와 함께 표시
- 받은 응원 문구 공유 카드
- 운영 통계와 문구별 반응 확인

### 3단계 — 실물/쿠폰 보상

- 재고, 당첨 수량, 유효기간, 지급 상태, 재발급 정책
- 당첨 고지 및 개인정보 동의
- 배송/쿠폰 공급자 연동

## 11. 완료 기준

- 인증하지 않은 사용자는 상자를 열 수 없다.
- 같은 인증일에 10번 요청해도 하나의 결과만 존재한다.
- 여러 기수가 동시에 있어도 4기 지급이 3기 기록과 섞이지 않는다.
- 운영자가 문구를 수정해도 과거 수령 문구는 유지된다.
- 모바일 320px부터 상자·문구·버튼이 잘리지 않는다.
- 키보드만으로 개봉할 수 있고 상태 변화가 스크린리더에 전달된다.
- 모션 감소 설정에서 흔들림·폭죽 없이 즉시 완료된다.

## 12. 현재 PoC와의 경계

`/poc/hello-2027`의 인증 완료 값과 운영 데이터는 로컬 예시이며 실제 계정·인증 DB가 아니다. 따라서 공개 크루 카드에 개봉 버튼을 넣거나 IndexedDB만으로 지급을 막는 방식은 운영 버전으로 사용하지 않는다. 먼저 4기 시즌·참가자·일일 인증 서버 저장 구조를 연결한 뒤 `/me`와 실제 `/admin`에 이 기능을 추가한다.

현재 저장소에는 메시지형 MVP의 `/api/me/gift-box`, `/me` 카드, `daily_gift_claims` 고유 제약이 추가됐다. 이 구현은 기존 승인 계정과 `daily_run_records`를 서버에서 재검증하므로 브라우저 상태만 믿는 방식보다 안전하지만, 아직 `season_id`가 없다. 3기·4기 데이터 백필과 동결을 완료하기 전에는 운영 지급을 활성화하지 않는다.
