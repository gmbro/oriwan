# 댓글 확인창·인증 승인 변경 — 로컬 검증

사용자 요청에 따른 로컬 변경이다. 기존 미커밋·미추적 작업과 환경설정은 보존했다. 운영 회원 데이터 변경, DB 초기화, 스키마 적용, 배포는 수행하지 않았다.

## 사용자 동작

- 댓글과 답글 삭제를 누르면 취소/삭제하기 확인창을 표시한다. 브라우저 최상위 모달을 사용해 `content-visibility` 영역과 내 정보 모달 안에서도 보인다. 취소를 기본 선택하며 Escape는 확인창만 닫는다. 관리자 댓글 삭제에도 같은 확인창을 사용한다.
- 4기 대시보드에서 9월 중순 오픈 안내 팝업을 제거한다.
- 개인 제출, 관리자 OCR, 관리자 직접 입력은 자동 인증하지 않는다. 개인 기록과 검수 대기로 접수하고 공식 인증은 관리자 승인 후 반영한다.
- 기준은 운동한 날 한국시간 00:00:00부터 07:59:59.999까지의 서버 업로드 접수다. 오전 08:00:00부터는 늦은 접수다. OCR 완료나 최종 제출 시각 때문에 정상 접수가 늦은 접수로 바뀌지 않도록 이미지 요청 본문을 받은 시각을 보존한다.
- 늦게 올린 기록은 인증샷에 표시된 같은 운동일과 오전 8시 이전 시각을 관리자가 직접 확인한다. 날짜·시각 입력과 확인 체크 후 승인할 수 있다. 운동 시간/페이스를 시각으로 간주하거나 OCR 추측으로 승인하지 않는다.
- 관리자는 날짜별 기록에서 ‘인증샷 확인 후 승인’을 누른다. 변경한 거리/시간은 먼저 저장한다. OCR 결과에서 날짜별 검수 화면으로 이동할 수 있다.
- 인증샷 없는 직접 입력은 검수 대기에 머문다. 관리자 이미지 올리기로 캡처를 등록한 후 승인한다. 같은 날짜 직접 입력으로 기존 기록을 덮어쓰지 않는다.
- 이미 승인된 기록은 자동 변경하지 않는다. 기존 검수 기록의 접수 시각을 확인할 수 없으면 캡처의 날짜·시각을 확인해야 승인할 수 있다.

## 서버 검증과 호환

업로드 접수와 승인 이력은 기존 비공개 `notes` 필드의 버전이 있는 영역에 보존한다. 별도 DB 변경 없이 적용하며 화면에는 내부 JSON을 표시하지 않는다. 사용자 요청의 업로드 시각이나 인증 상태는 신뢰하지 않는다. 관리자 메모 수정도 서버가 저장한 접수 시각을 바꾸지 못한다.

승인에는 관리자 권한, 인증샷, 멤버·날짜·유효한 기록, 명시적 확인과 마감 조건이 필요하다. 검토하던 이미지·메모가 바뀌었거나 저장 도중 다른 요청이 수정했으면 409로 중단한다. 승인 기록의 날짜·멤버를 옮기면 다시 검수한다. 공용 통계는 기존처럼 `certified`만 집계하고 개인 검수 대기 거리/시간의 기존 의미는 유지한다.

## 검증

- 자동 테스트 135개 통과: 기존 122개 + 마감/승인 정책 4개 + 실제 관리자 라우트에 가짜 DB·인증을 주입한 9개.
- TypeScript, 변경 TS/TSX ESLint, Next.js 운영 빌드, 실행 사본의 `git diff --check` 통과.
- 브라우저 가상 데이터: 댓글/답글 확인창, 취소 시 요청 0회, 모달 안의 확인창과 Escape, 답글 삭제, 삭제 실패 복원, 08:00 승인 차단, 같은 날 07:59 캡처 확인 후 승인.
- 실제 인증 이미지 업로드/OCR·회원 삭제·운영 인증 승인은 실행하지 않았다. 새 규칙은 아직 운영 사이트에 반영되지 않았다.
