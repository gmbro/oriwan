# TWTT 관람·응원·참여 전환 기획

2026-09-13 조사. 공개 관람석과 가입 분리는 신규 기획이며 이 문서 작성으로 운영 서비스의 권한·검색 설정을 변경하지 않는다. 기존 홈페이지 기획의 확장안으로, 로그인과 참가를 동일하게 취급하던 부분은 아래 정책으로 대체한다.

## 1. 권장 방향

**로그인 없이 구경 → 가볍게 응원 → 다음 이야기를 보러 재방문 → 직접 참가 또는 교정운동 문의**의 흐름을 만든다. 러닝을 하지 않는 사람도 관객·응원단으로 남을 수 있어야 한다. 광고 수를 늘리는 것보다 방문할 이유를 매일 만드는 것이 먼저다.

대표 콘셉트: **스내사 100일 레이스 관람석**. 승인된 운동 기록을 캐릭터의 여정으로 표현하고 오늘의 변화·주간 회고·다음 공동 목표를 보여준다. 실제 GPS 생중계가 아니라 ‘승인 기록으로 보는 레이스’라고 명시한다. 새 기록이 없어도 캐릭터가 달리는 연출 때문에 거리가 증가하거나 실제 운동 중인 것으로 오해하게 하지 않는다.

별도 도메인은 필요 없다. 같은 도메인의 `/`를 공개 TWTT 홈으로 바꾸고 `/snasa/4`를 소개와 관람석의 대표 페이지로 사용한다. `/4th/dashboard`는 기존 인증 서비스와 상세 기록 화면으로 유지한다. 기존 URL을 검색 가능하게 만드는 것도 기술적으로 가능하지만, 공개 데이터와 회원 기능이 섞여 있어 첫 출시에서는 분리하는 편이 명확하다.

## 2. 현재 서비스에서 확인한 사실

| 확인 대상 | 실제 결과 | 의미 |
| --- | --- | --- |
| 운영 도메인 `/` | `/4th`로 이동, 최종 HTTP 200 | 독립 공개 소개 홈이 아직 없음 |
| `/4th` | robots 메타 `noindex, nofollow` | 검색 색인 제외 설정 |
| `/4th/dashboard` | HTTP 200, `noindex, nofollow` | 방문은 가능하지만 Google에 색인하지 말라고 알리는 상태 |
| `/robots.txt`, `/sitemap.xml` | 모두 HTTP 404 | 검색 안내·사이트맵이 없음. 이 사실만으로 색인이 불가능해지는 것은 아님 |
| 로그인 콜백 | `ensureParticipantAccount` 호출 | 로그인 후 참가 연결·자동 생성 가능 |
| 개인 정보 API 공통 컨텍스트 | 같은 자동 등록 함수 호출 | 콜백만 고쳐도 다른 API에서 자동 등록이 다시 일어날 수 있음 |
| 자동 등록 함수 | 참가자 upsert 및 계정 approved 저장 | 일반 관람 계정과 참가자를 분리해야 함 |

코드 근거: `app/page.tsx`, `app/4th/page.tsx`, `app/4th/dashboard/page.tsx`, `app/api/auth/callback/route.ts`, `lib/personal-member-context.ts`, `lib/participant-account-server.ts`.

현재 Google 색인 목록·검색 순위·수동 조치 여부는 Search Console 소유자 데이터에 접근하지 않아 확인하지 않았다. 확인한 것은 배포 응답의 차단 설정이다. ‘도메인 자체가 Google에서 금지되었다’는 근거는 없다.

위 표의 TWTT 적용안은 사례를 참고한 제안이며 각 서비스가 동일한 익명 관람 기능을 제공한다는 주장은 아니다. 특히 Zwift의 현재 비로그인 웹 관전 가능 여부는 이번 조사에서 검증하지 않았다. 벤치마크 사업자의 마케팅 성과 수치를 TWTT 예상 성과로 사용하지 않는다.

## 4. 로그인과 도전 참가 분리

| 사용자 | 가능한 행동 | 회원 수·공식 기록 |
| --- | --- | --- |
| 비로그인 관객 | 관람석·이야기·운동 콘텐츠·광고 보기, 정해진 응원 누르기, 참여 방법과 문의 열기 | 참가자 수에 포함하지 않음 |
| 로그인 응원단 | 응원 대상 저장, 댓글·알림 신청, 참가 신청 상태 확인 | 로그인만으로 참가자 생성 금지 |
| 참가 신청자 | 규칙·일정·비용 확인 후 신청, 운영자 답변 확인 | 승인 전 명단·거리 분모에 미포함 |
| 승인된 도전자 | 인증 제출·개인 기록·기존 보상 기능 | 실제 활성 참가자만 집계 |
| 운영자 | 참가 승인, 인증 승인, 공개 콘텐츠·신고·광고 관리 | 참가 승인과 운동 기록 승인을 별개로 관리 |

버튼은 ‘로그인’과 ‘도전 참가 신청’을 분리하고 로그인 근처에 **로그인만으로 도전에 참가하지 않아요**라고 안내한다. 로그인 후에도 보던 관람석으로 돌아온다. 기존 도전자는 바로 내 활동을 이용한다.

구현 시 인증 신원 확인과 참가자 조회를 읽기 전용으로 만들고 자동 등록 호출을 콜백·`/api/me`·개인 기능 공통 경로 전체에서 제거한다. 명시적 참가 신청 API와 운영자 승인에서만 참가자를 생성·연결한다. 신청은 사용자·시즌 단위로 중복 방지한다. 기존 회원과 기록은 보존하며 ‘기록이 없으니 관객’이라는 추정으로 자동 탈퇴시키지 않는다. 관객·대기자·승인·철회 상태별 접근 테스트가 출시 조건이다.

## 5. 공개 관람석 화면

모바일 첫 화면은 **스내사 4기 · 100일의 여정 / 짧은 소개 / 레이스 / 응원하기 / 참여 방법** 순서다. 상세 설명을 읽기 위해 로그인하지 않는다.

1. **레이스 무대**: 공개 동의한 닉네임·아바타. 한 명을 누르면 해당 캐릭터를 따라보는 간단한 모드. 오늘/이번 주/시즌 기준을 분명하게 표시한다. 모바일 캐릭터 과밀은 그룹으로 묶고 선택 시 확대한다.
2. **공동 목표**: 현재 목표와 승인 누적 거리, 마지막 갱신 시각. 기존 1,000 → 2,027 → 5,000 → 10,000km 단계 유지. 달성 전 다음 목표는 숨긴다.
3. **오늘 달라진 점**: 승인된 사실만으로 ‘오늘 새 인증 N건’, ‘공동 목표까지 Nkm’를 생성. 0건이면 준비·휴식 상태를 솔직하게 표시한다.
4. **응원**: ‘오늘도 응원해요’, ‘꾸준함이 멋져요’, ‘함께 완주해요’ 세 버튼. 말풍선과 손 흔들기만 표현. 비로그인 횟수는 사람 수로 부르지 않고 ‘응원 횟수’로 표시한다.
5. **이번 주 이야기**: 공개에 동의한 완주·복귀·꾸준함 사례 1~3개와 지난주 회고. 빠른 사람만 주인공이 되지 않도록 운영자가 선정한다.
6. **러너를 위한 교정운동 콘텐츠**: 운영자가 직접 만든 짧은 영상·설명 1개, ‘프로그램 자세히 보기’ 연결.
7. **파트너 카드**: 광고 표시와 혜택·대상·기간·링크. 처음에는 무대 아래 한 곳과 콘텐츠 사이 한 곳을 상한으로 시험한다.
8. **참여 방법·FAQ·문의**: 나도 참가하기 / 다음 기수 소식 받기 / 운영자에게 문의하기. 모집 상태에 따라 버튼을 바꾼다.

화면에서 보이지 않는 캐릭터 애니메이션은 멈추고 탭 비활성 때 갱신을 중단한다. 3D 엔진·자동 재생 고화질 영상 대신 기존 배경과 SVG/CSS 움직임을 재사용한다. 공개 집계는 캐시하고 승인 변경 시 갱신하며, 초기에는 화면이 열린 동안 60초 간격 갱신이면 충분하다. 새 승인 때만 이동 연출을 짧게 재생하고 ‘승인 기준, 실시간 위치 아님’을 표시한다.

## 6. 공개 데이터와 응원 운영

기존 ‘로그인해야 다른 사람의 상세 기록을 본다’는 정책은 유지한다. 공개 관람용으로 별도 동의한 닉네임·아바타·집계 지표만 제공한다. 로그인 여부와 검색 공개 동의는 별개다. 동의하지 않은 참가자는 공동 합계에만 반영하고 식별 가능한 캐릭터·개인 수치는 내보내지 않는다.

공개 API는 필요한 필드만 새로 구성한다. 인증 캡처, 실제 경로, 시작 시각, 카카오 식별자, 연락처, 비공개 타임머신 목표는 제외한다. 공개 철회 시 페이지·캐시·공유 카드도 갱신한다. 이미 외부에 공유되거나 검색된 자료의 즉시 완전 삭제는 보장하지 않는다.

익명 응원은 서버 속도 제한·일별 제한·서명된 익명 식별값으로 과도한 반복을 줄인다. 익명 사용자의 완벽한 1인 판별은 불가능하므로 경품·금전·공식 점수와 연결하지 않는다. 자유 댓글은 로그인 후 가능하게 하되 관람 회원 상태를 유지하고 신고·숨김·관리자 제재를 제공한다. 초기는 정해진 응원만 먼저 출시한다.

## 7. 교정운동 홍보와 콘텐츠

운영자만 할 수 있는 실제 설명과 시연을 브랜드의 이유로 만든다. 순위표만으로는 지인을 모르는 관객이 계속 방문하기 어렵다.

- 주 1회: 운영자 이름·실제 소개·촬영 날짜를 담은 짧은 동작 설명 영상과 읽을 수 있는 본문.
- 주 1회: 스내사 주간 회고. 승인 기록의 공동 변화와 동의한 도전자 이야기.
- 월 1회: 교정운동 모임 후기·다음 일정. 사진과 후기는 당사자 동의 후 게시.
- 첫 검색용 글: ‘스내사는 어떻게 참여하나요?’, ‘아침 러닝 인증은 어떻게 하나요?’, ‘TWTT 교정운동 프로그램은 어떻게 진행되나요?’.

콘텐츠 → 프로그램 소개 `/movement` → 가능한 일정·장소·시간·가격·대상 → 문의/신청으로 연결한다. 실제 운영 지역이 확정되기 전 ‘강남 수업’이라고 쓰지 않는다. 강남 날씨 사용은 수업 장소의 근거가 아니다. 자격·효과·후기를 만들어내거나 치료를 보장하지 않는다. 이 문서는 운동 처방을 제안하지 않으며 실제 동작 내용은 운영자가 검토해 발행한다.

## 8. 참가 안내와 문의

참여 방법은 **모집 확인 → 신청 → 운영자 확인 → 참가 확정 → 인증 시작**을 그림 없이도 읽을 수 있는 HTML 본문으로 제공한다. 기간·정원·비용·중도 참가 가능 여부·초보자 기준·취소 방식·운영자 응대 시간을 적는다. 미확정 항목은 임의의 숫자로 채우지 않는다.

공개 FAQ 예시: ‘로그인하면 자동 가입되나요?’ → ‘아니요. 도전 참가 신청 후 운영자가 확정해요.’ / ‘구경만 해도 되나요?’ → ‘로그인 없이 구경하고 응원할 수 있어요.’ 이 문구는 가입 분리가 구현된 뒤 공개한다.

문의는 비공개 폼: 분류(참가/교정운동/광고/기타), 회신 방법, 연락처, 내용, 필요한 개인정보 안내. 로그인은 선택. 로그인한 경우 내 문의에서 상태 조회, 비로그인은 실제 회신 채널로 답변한다. 공개 게시판에 전화번호·건강정보를 남기게 하지 않는다. 스팸 제한과 운영자 알림을 붙인다. 운영자 문의 채널과 폼 저장·보관 정책이 확정되기 전 작동하는 것처럼 보이는 버튼은 공개하지 않는다.

어드민 탭: 참가 신청 / 공개 프로필 동의 / 주간 이야기 / 교정운동 일정 / 문의함 / 광고. 문의는 신규·답변 중·완료, 담당·처리 시각을 기록한다. 기존 선물 관리 탭과 구독 혜택은 재사용하되 실제 재고·제공 가능 여부를 확인한다.

## 9. 광고 노출과 성과

첫 상품은 기존 월 10,000원 광고를 유지하되 관람석 포함 여부·기간·위치를 명시한다. 이후 방문량이 확인되면 ‘주간 여정 파트너’나 교정운동 콘텐츠 협찬을 별도로 구성한다. 광고 클릭이 없어도 관람은 계속 가능하며 보상 열기를 광고 클릭으로 강제하지 않는다. 후원과 광고 구매는 분리한다.

측정은 페이지 로드 수가 아니라 실제 화면에 나타난 광고를 기준으로 한다. 초기 내부 기준 예: 카드 50% 이상이 1초 이상 보이고 탭이 활성일 때 소재·세션 단위 1회 인정. 이는 자체 분석 기준이며 인증된 광고 측정 서비스라는 뜻은 아니다. 자동 로테이션·새로고침·운영자 점검을 노출로 부풀리지 않는다.

| 목표 | 지표 |
| --- | --- |
| 구경할 이유 | 관람 시작, 무대 상호작용, 7일 재방문 |
| 광고 가치 | 유효 노출, 광고 클릭, 문의 완료 |
| 커뮤니티 성장 | 참여 방법 열람 → 신청 완료 → 참가 승인 → 첫 공식 인증 |
| 교정운동 성장 | 콘텐츠 열람 → 프로그램 상세 → 문의 → 실제 예약 |

로그인 수를 참가자 증가로 계산하지 않는다. 익명 방문은 기기·브라우저 기반 추정임을 표시한다. 첫 2주 기준선을 만든 뒤 다음 2주에 카드 순서·CTA 문구 하나씩 비교한다. 트래픽이 적으면 전환율만 보지 말고 실제 문의 수와 문의 이유를 함께 검토한다. 초기 성과·방문자 수를 임의로 약속하지 않는다.

## 10. Google 검색 노출 계획과 불가능한 보장

현재 가장 직접적인 차단 요인은 배포 HTML의 `noindex`다. Google은 이 규칙을 보면 페이지를 검색 색인에서 제외한다. [Google noindex 설명](https://developers.google.com/search/docs/crawling-indexing/block-indexing).

공개 홈페이지와 관람석을 만들 때 해당 공개 페이지만 색인을 허용한다. 서버 HTML에 TWTT·스내사 소개, 기간, 참가 방법, 공개 집계, 이야기 본문을 제공한다. 모션만 있고 설명이 없거나 로그인 후에만 본문이 나타나면 검색 입구로 적합하지 않다. 개인·관리자 화면은 권한 검사와 검색 제외를 유지한다.

페이지별 제목·설명·canonical·공유 이미지를 작성하고 실제 링크로 연결한다. `/`·`/snasa/4`·발행된 `/stories/[slug]`·`/movement`·실제 모임 상세를 사이트맵에 포함한다. 필터 URL·내 정보·API·미발행 글은 제외한다. robots.txt에서 공개 페이지의 크롤링을 막지 않는다. 구조화 데이터는 실제 본문과 일치하는 Organization·Article·실제 행사 Event만 사용하고 별점·행사를 만들어내지 않는다.

Search Console은 도메인 소유권 확인이 가능하면 DNS 방식, 하위 도메인 DNS 관리가 어렵다면 HTTPS URL-prefix 속성의 HTML 메타 방식 등을 확인한다. 사이트맵 제출 후 URL 검사에서 실제 페이지 테스트와 색인 요청을 수행한다. 재수집 요청이나 사이트맵이 색인·상위 노출을 보장하지 않는다. [Google 재수집 안내](https://developers.google.com/search/docs/crawling-indexing/ask-google-to-recrawl), [사이트맵 설명](https://developers.google.com/search/docs/crawling-indexing/sitemaps/overview).

검색이 안 될 때 확인 순서: noindex → robots/로그인/HTTP 오류 → canonical·중복·리디렉션 → 발견·크롤링 상태 → 본문과 내부 링크 → 콘텐츠 품질·검색 수요. .kro.kr 또는 한글 주소라는 사실만으로 검색 불가능하다고 판단할 근거는 이번 조사에서 없다. 장기 브랜드용 독립 도메인은 선택 사항이고 지금의 차단 설정을 자동 해결하지 않는다.

## 11. 실행 우선순위와 완료 기준

1. **가입 분리와 공개 범위 확정**: 신규 관객 로그인·개인 API 조회로 참가자가 늘지 않음. 기존 회원 기록 유지. 공개 동의 없는 개인 데이터가 응답에 없음.
2. **공개 홈·관람석·참가 안내·문의**: 비로그인 휴대폰에서 구경부터 문의까지 가능. 문의 저장·운영자 확인·회신 경로 검증. 대표 페이지 HTTP 200과 검색 허용 확인.
3. **검색 기본 설정·콘텐츠 3건**: 서버 본문·canonical·사이트맵 확인, Search Console 실제 상태 확인. 색인 미완료라면 원인을 기록하고 완료라고 보고하지 않음.
4. **응원·주간 이야기·교정운동 소개**: 공식 기록과 응원 수 분리, 실제 콘텐츠와 일정으로 운영. 기존 캐릭터를 활용해 속도·모바일 검증.
5. **광고 측정·주간 파트너**: 실제 노출과 문의가 집계된 뒤 상품 확장. 3D 레이스·실시간 채팅·관객 경품은 초기 범위에서 제외.

착수에 필요한 운영 정보: 공식 문의 채널, 참가비·모집 상태·중도 합류 정책, 공개 프로필 동의 방식, 교정운동 실제 장소·가격·시간·소개 자료. 추천 첫 개발 묶음은 1~3단계다. 이후 매주 이야기와 운동 콘텐츠를 운영할 수 있어야 관람석이 지속적인 유입 경로가 된다.

## 2026-09-14 참관객 정책 구체화 (신규 기획)

사용자 추가 방향: 비로그인 관객에게 멤버 이름·승인된 누적 거리·총 운동 시간을 보여준다. 하루 기본 응원은 동일 IP에서 1회이며, 추가 1회는 광고 시청 후 가능하게 한다. 이 문단은 앞으로의 공개 관람석 정책이며 기존 상세 인증 캘린더·원본 공개를 뜻하지 않는다. 이번 코드 배포에서는 멤버 승인제·댓글 보호·자기소개·교정운동 콘텐츠까지만 변경하고 관객 응원 기능은 아직 구현하지 않는다.

권장 첫 규칙은 ‘크루 전체에서 하루 기본 응원 1개 + 추가 응원 1개, 총 2개’다. 멤버마다 1회로 만들면 멤버 수만큼 광고·응원 반복이 생기므로, 먼저 한 멤버를 골라 응원하는 구조로 시작한다. 같은 멤버에게 두 번 응원할 수는 있지만 공식 거리·인증률·상품 확률에는 영향을 주지 않는다. 일자는 한국 시간 자정에 바뀐다. 보유 추가 응원은 당일에만 사용한다. 추가 횟수는 제안 상한이며 사용자 확정 전 무제한 광고 반복을 구현하지 않는다.

응원 상태: 무료 1개 사용 가능 → 기본 응원 완료 → ‘광고 시청하고 응원 1회 더 받기’ 선택 → 완료 확인 → 추가 응원 1개 지급 → 사용할 멤버 선택 → 오늘 응원 완료. 광고 없음·실패·중도 닫기는 추가 횟수를 소모하지 않고 기존 관람 기능을 유지한다. 완료 이벤트 재전송·다중 탭에서도 추가 지급·소비는 각각 한 번만 가능해야 한다.

IP는 사람과 동일하지 않다. 같은 집·회사·통신사 공유 IP는 기본 응원을 나눠 쓰게 될 수 있고, VPN·IP 변경은 우회 가능하다. ‘같은 네트워크에서는 하루 1회 무료 응원이 가능해요’라고 안내한다. 신뢰하는 배포 프록시가 제공한 IP만 사용하고 사용자 입력 X-Forwarded-For를 그대로 신뢰하지 않는다. IPv4/IPv6 정규화와 IP 기반 HMAC·일자 키를 사용하고 원시 IP 장기 보관을 피한다. 일자·IP키·무료/추가 구분의 DB 고유 제약과 원자적 소비로 여러 서버 인스턴스에서도 중복을 막는다. 이는 비로그인 완벽한 1인 판별을 보장하지 않는다.

광고를 다른 탭에서 클릭하고 돌아왔다는 사실만으로 시청 완료를 확인할 수 없다. 초기 직접 판매 광고라면 동의한 광고주의 콘텐츠를 사이트 안에서 보여주고 ‘사이트 내 파트너 소개 열람’으로 별도 집계한다. 외부 방문·영상 완주·검증된 광고 노출로 과장하지 않는다. Google 광고라면 일반 배너 클릭에 보상을 걸지 않고, 사용 가능한 보상형 웹 광고 상품·계정 승인을 확인해야 한다. 서버 검증 가능한 완료 신호가 없는 구현은 위조 방지 한계가 있으며 지급·세션 중복 방어가 별도로 필요하다.

Google 보상형 광고는 사전 행동·보상 설명과 이용자 선택이 필요하다. 응원권은 사이트 내 비금전성 기능으로 한정하고 현금·쿠폰·실물 경품으로 바꾸지 않는다. ‘광고를 눌러 운영자를 도와주세요’ 같은 클릭 유도 대신 실제 보상만 안내한다. 정책 충족이나 광고 공급은 구현만으로 보장되지 않는다. [Google 보상 정책](https://support.google.com/adsense/answer/9121589?hl=en), [웹 보상형 광고 예제](https://developers.google.com/publisher-tag/samples/display-rewarded-ad).

도메인 후보 `archi-landing.cloud`는 사용 가능하지만 .cloud라는 확장자가 검색 순위를 유리하게 만들지 않는다. 이름에 스내사가 없어 기억·브랜드 연결에는 기존 이름보다 불명확할 수 있다. 독립 도메인을 장기 관리할 수 있다는 운영상 장점과 SEO 우위를 구분한다. [Google 도메인 관련 FAQ](https://developers.google.com/search/help/site-position-in-search-faq).

도메인 변경은 아직 수행하지 않는다. 이 도메인이 다른 서비스를 운영한다면 루트를 덮어쓰지 않고 별도 스내사 서브도메인을 검토한다. 옮기기로 확정하면 DNS·Vercel 연결·HTTPS·카카오 반환주소·SITE_URL·canonical·사이트맵·이전 URL의 301을 함께 처리해야 한다. 두 도메인에 같은 홈페이지를 독립적으로 중복 운영하지 않는다. Search Console ‘도메인’ 속성에는 프로토콜 없이 archi-landing.cloud를 입력하고, 발급된 TXT를 DNS에 추가해 검증한다. 속성 등록만으로 TWTT가 해당 도메인에 배포되지는 않는다.
