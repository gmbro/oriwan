# 스내사 관람·응원·참여 전환 기획

2026-09-14 개정. 이 문서는 신규 관람석과 응원·광고 정책의 제안이다. 아래 응원 기능은 아직 구현하지 않았다. 공개 기록 관람은 후속 배포에 반영했으며 docs/release-public-spectator-2026-09-14.md에 범위를 기록했다. 이전의 ‘동일 IP 하루 1회’를 유일한 제한으로 쓰는 안을 대체한다.

## 1. 목적과 제품의 중심

**멤버의 꾸준한 변화를 보러 와서 응원하고, 다음 변화를 보러 다시 오는 관람석**을 만든다. 광고를 보기 위해 반복 클릭하는 서비스가 되면 광고 품질과 운동 동기가 함께 나빠진다. 방문할 이유는 승인된 러닝 기록의 변화이고, 광고는 그 여정을 후원하는 파트너로 노출한다.

우선순위는 ① 실제 관람객의 재방문 ② 멤버의 인증 지속 ③ 유효한 광고 도달 ④ 참가 문의와 승인 참가 전환이다. 응원 횟수·페이지뷰 총량만을 성공 기준으로 삼지 않는다.

## 2. 현재 상태와 신규 범위

- 현재 공개 홈은 스내사 소개·참여 방법을 제공한다. Search Console 소유권 확인, 사이트맵 제출 및 홈 색인 요청을 완료했다. 색인·검색 순위는 보장하지 않는다.
- 카카오 로그인 후 운영자 승인 전에는 멤버가 되지 않는다. 댓글은 승인된 멤버에게만 보인다.
- 관람석의 이름·승인 누적 거리·누적 시간·이번 주 합계 공개는 반영했다. 익명 응원과 광고 보상은 신규 개발 범위다. 상세 기록은 회원 보호를 유지한다.
- 이번 수정으로 대시보드의 교정운동 영상 영역을 제거한다. 콘텐츠를 억지로 늘리기보다 레이스 변화부터 관람할 이유를 만든다.
- 후원의 완료 버튼과 쉬어가기 안내는 제거한다. 외부 송금·선물 완료를 자동으로 확인할 수 없으므로 ‘월 1회 후원 제한을 결제 차원에서 강제한다’고 설명하지 않는다. 과거 완료 기록에 대한 제한은 기존 상태대로 남는다.

## 3. 관람객 경험

1. 로그인 없이 오늘의 공동 거리, 이번 주 변화, 멤버 이름·승인된 누적 거리·시간을 본다. 공개 이름은 본인이 동의한 표시 이름을 사용하고 비공개 요청을 처리한다. 운동 경로·원본 인증 사진·시각별 생활 패턴·댓글은 공개하지 않는다.
2. 멤버 또는 크루 전체에 ‘응원 보내기’를 누르면 짧은 손 흔들기와 ‘응원이 전달됐어요’가 나온다. 공식 거리·인증률·순위는 바뀌지 않는다.
3. ‘오늘은 여기까지, 내일의 변화도 함께해요’로 마무리한다. 다시 새로고침하거나 광고를 연속 재생할 이유를 주지 않는다.
4. 참가에 관심 있는 사람에게 모집 조건·기간·운영자 문의·카카오 참여 신청을 안내한다. 로그인과 실제 참가 승인은 분리한다.

레이스는 GPS 생중계가 아닌 승인 기록의 시각화다. 뛰는 애니메이션만으로 기록이 늘어나지 않는다. 새 기록이 없는 날은 지난 주 변화나 다음 공동 목표를 보여주며 활동을 꾸며내지 않는다.

## 4. 응원 수량과 정체성: IP는 사람이 아니다

**추천 기본값: 브라우저/계정당 하루 무료 응원 1회, 보상형 광고로 추가 1회, 크루 전체에서 합계 최대 2회.** 한국 시간 자정 초기화, 미사용분 이월 없음. 같은 멤버에게 두 번 보내는 것은 허용하되 ‘응원 2회’를 ‘관람객 2명’이라고 표시하지 않는다.

- 익명 방문자: 서버 발급 서명된 임의 식별자를 HttpOnly 쿠키로 보관한다. 지문 수집은 하지 않는다. 삭제·시크릿·기기 변경을 통한 우회는 완전히 막을 수 없다.
- 로그인 방문자: 계정별 한도를 우선하고 같은 브라우저의 사용량을 합산해 로그인 전후 이중 지급을 막는다. 로그아웃해도 해당 브라우저의 당일 사용량은 유지한다.
- IP: 신뢰한 프록시에서 얻은 주소를 위험 신호로만 사용한다. 하루별 비밀키 HMAC으로 처리하고 원문 IP를 응원 데이터에 저장하지 않는다. 원문 헤더를 무조건 신뢰하지 않는다.
- 같은 집·회사·카페·통신망의 여러 사람: IP가 같아도 각 브라우저의 기본 응원은 허용한다. IP 단위 1회 차단은 정상 관객을 가장 먼저 막으므로 채택하지 않는다.
- 장기 익명 신원 보장을 약속하지 않는다. 조작으로 얻을 실익을 없애고 이상 패턴의 집계·광고를 제한하는 것이 비용 대비 효과적이다.

## 6. 동기부여는 인기 경쟁과 분리

- 운동 성과는 승인된 인증·거리·꾸준함으로만 계산한다. 응원과 광고 시청으로 기록을 가산하지 않는다.
- 멤버에게는 하루 한 번 묶어서 ‘오늘도 응원이 도착했어요’를 보여준다. 응원 0회 경고·인기 꼴찌·과도한 알림을 만들지 않는다.
- 공개 화면은 공동 여정과 최근 변화를 중심으로 한다. 개인 응원 순위표와 실시간 숫자 경쟁은 초기에는 두지 않는다.
- 응원 보상은 사이트 안의 짧은 표현/애니메이션에 한정한다. 현금·쿠폰·경품 확률·인증박스 보상과 연결하지 않는다.
- 개인 ‘응원 횟수’와 추정 ‘고유 브라우저 수’를 구분한다. 고유 브라우저를 실제 사람 수라고 주장하지 않는다.

## 7. 광고 모델: 먼저 직접 파트너, 이후 보상형 실험

### 1단계: 문맥에 맞는 직접 후원 광고

‘이번 주 여정을 함께하는 파트너’ 한 자리를 기본으로 한다. 광고임을 명확히 표시하고 레이스/주간 변화와 자연스럽게 이어 붙인다. 초기에는 기간 정액형 파트너십을 제안하고 노출·문의 수를 보장하지 않는다. 숨겨진 영역, 자동 새로고침, 응원 클릭 직전의 광고 겹침은 금지한다.

광고주에게는 총 노출뿐 아니라 추정 도달 브라우저, 빈도, 이상 트래픽 제외 기준, 문의 전환을 함께 제공한다. 자체 화면 가시성 측정은 내부 지표로 표기하고 광고 네트워크의 공식 유효 노출과 혼동하지 않는다. 같은 사람의 재방문은 동기부여 성과일 수 있지만 새로운 광고 도달로 계산하지 않는다.

### 2단계: 선택형 보상 광고

공급자 승인·웹 지원·완료 검증·운영 비용이 확인된 경우에만 소규모 실험한다. 사용자가 ‘광고 시청 후 응원 1회 추가’를 명시적으로 선택하고, 중단할 수 있으며, 하루 한 번만 가능하다. 기본 응원 뒤 강제 전체화면 광고는 사용하지 않는다.

일반 배너 클릭이나 외부 탭 방문을 시청 완료로 인정하지 않는다. Google 광고를 이용하면 허용된 보상형 형식과 해당 정책을 따라야 한다. ‘광고를 클릭해 우리를 도와주세요’ 등의 유도는 하지 않는다. 허위·반복 노출은 지속가능한 매출이 아니다.

보상형은 추가 도달을 만드는 기능이 아니다. 기존 관객의 노출 빈도를 높이는 실험이므로 신규 관객 확보는 공유 가능한 주간 회고·모집 안내·검색 가능한 소개에서 만든다.

## 8. 서버 운영과 비용

- `cheer_events`: 요청 키, 날짜, 브라우저/계정 식별자, 수신 대상, 무료/보상 구분, 처리 상태. 같은 요청의 재시도는 같은 결과를 반환한다.
- `daily_quota`: KST 날짜와 주체의 고유 제약, 무료/보상 사용량. 지급과 소비를 DB 트랜잭션으로 처리한다.
- `reward_sessions`: 사용자·당일에 결합된 만료 토큰과 공급자 완료 ID. 세션 하나당 한 번만 지급한다. HTTP 성공이나 클라이언트 타이머만으로 지급하지 않는다.
- 확인된 이벤트만 집계하며 의심 이벤트는 운영자 검토 대상으로 분리한다. 전체 공개 목록은 짧게 캐시하고 응원 입력만 별도 API로 처리한다. 광고 SDK는 선택/가시성 시점에 지연 로딩한다.
- 제안 보관 기간: IP HMAC 위험 신호 7일, 상세 응원/오류 이벤트 30일 이후 삭제 또는 비식별 집계. 실제 수집 필드·기간은 출시 전 개인정보 안내에 반영한다.
- 운영자 기능: 일별 유효/의심 이벤트, 광고 오류·공급 없음, 제한 복구, 광고 기능 즉시 중단. 광고 수익보다 조사·응대 비용이 커지면 보상형을 중단할 수 있어야 한다.

## 9. 단계별 출시와 중단 기준

1. **기본 관람석 2주:** 승인 누적 지표·무료 응원·일별 순환 노출·모집 안내. 광고 추가 응원은 닫아 둔다. 주간 재방문, 멤버 인증 지속률, 기본 응원 실패, 공유 IP 오차를 측정한다.
2. **직접 파트너 2~4주:** 광고 슬롯 하나, 반복 방문 빈도 제한, 클릭/문의 계측. 기존 구간과 비교하되 멤버 수·요일 차이를 기록한다.
3. **보상형 소규모 실험:** 공급자 요건 충족 후 일부 세션에만 제공하고 미제공 집단과 비교한다. 제공 비율과 한도는 운영자가 조정한다.

운영 경보의 초기 제안값: 기본 응원 오류율 1% 초과, 광고 추가 후 이탈률 5%p 증가, 의심 이벤트 비율 10% 초과, 모바일 LCP p75가 기준보다 0.5초 이상 악화되면 보상형을 일시 중단하고 원인을 확인한다. 소규모 표본에서는 비율만으로 결론 내리지 않고 실제 건수·문의 내용을 함께 본다. 광고 공급자의 정책 경고는 즉시 중단 조건이다. 이는 관측 결과가 아닌 출시 전 정할 운영 기준이다.

매주 볼 지표는 재방문 관람객 비율, 멤버 주간 인증 지속률, 유효 응원 도달 멤버 비율, 광고 순수익, 광고 오류/이탈, 참가 문의→승인 전환이다. 순수익은 광고 수입에서 서빙·개발 유지·부정행위 대응 비용을 뺀다. eCPM과 방문량을 아직 모르므로 수익을 예측하거나 보장하지 않는다.

## 10. 도메인과 검색

현재 `https://스내사.kro.kr/`의 공개 홈을 우선 유지한다. `archi-landing.cloud` 자체의 검색 가산점은 없고 스내사 브랜드와 주소의 연관성도 약하다. 사용하려면 기존 서비스 유무, DNS/HTTPS, 대표 URL, 기존 주소의 영구 리디렉션, 카카오 콜백, 사이트맵을 함께 정리해야 한다. 이번 기획으로 도메인을 이전하지 않는다.

공개 관람석을 검색에 열 때는 서버에서 공개 전용 필드만 내려주고, 로그인 여부에 따라 댓글 제목·개수·본문까지 누출되지 않게 한다. 로그인 숨김 UI만으로 개인정보 보호를 대신하지 않는다.

## 11. 공식 근거

- [Google 보상형 광고 정책](https://support.google.com/adsense/answer/9121589?hl=en): 자발적 선택, 허용 보상과 표시 기준.
- [Google 무효 트래픽 정의](https://support.google.com/adsense/answer/16737?hl=en): 인위적인 클릭·노출, 운영자 본인 광고 조작 위험.
- [Google 광고 프로그램 정책](https://support.google.com/adsense/answer/48182?hl=en): 광고 클릭 유도 금지.
- [웹 보상형 광고 예제](https://developers.google.com/publisher-tag/samples/display-rewarded-ad): 공급자 이벤트 기반 구현의 출발점. 사용 승인이나 서버 검증 제공을 보장하는 자료는 아님.
- [Google의 새 최상위 도메인 처리](https://developers.google.com/search/blog/2015/07/googles-handling-of-new-top-level): 도메인 확장자만으로 검색 우위를 기대하지 않음.

**최종 권장:** 공유 IP의 정상 관객을 막지 않고, 자기 응원·우회로 얻는 실익을 없애며, 공동체의 변화와 직접 파트너 광고부터 검증한다. 보상형 광고는 유지율과 순수익이 확인될 때만 확대한다.
